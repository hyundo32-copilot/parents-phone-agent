# 폰 도우미 (parents-phone-agent) — 1단계 프로토타입

연로한 부모님이 쓰는 갤럭시 폰의 정상 설정을 **기준 스냅샷**으로 찍어 두고, 주기적으로 비교해 벗어난 항목을 **자동으로 되돌리는** 가족용 사이드로드 Android 앱입니다. 설치와 기준 촬영은 부모님이 보는 앞에서 하고, 복원 전에는 음성으로 알리며 화면의 큰 **중단** 버튼으로 언제든 멈출 수 있습니다. 설계 기준: [`docs/기획서-설계/design-snapshot-restore.md`](docs/기획서-설계/design-snapshot-restore.md) (1단계 범위만 구현). 기획서·설계·검토·수정 이력은 [`docs/`](docs/)에 정리돼 있다. UI 2차(기록 분리·타일 버튼·결과 카드·읽어 주기)까지 완료했고, 단위 테스트 316개가 전부 통과한다.

수집하지 않는 것: 메시지·통화 내용, 사진, 전체 연락처, 비밀번호. 스냅샷은 설정값만 저장하며 기기 안에만 둡니다 (`allowBackup=false`).

## 구현 범위 (1단계)

- 기준 스냅샷 찍기 + 주기 점검(하루 2회 08시·19시 알람, 잠금 해제 후 첫 점검은 6시간 간격 제한) + 수동 점검
- A등급 자동 복원: 무음/벨소리 모드·볼륨, 방해금지, 비행기 모드, Wi-Fi, 모바일 데이터, 전화·문자 앱 알림 (각각 안전 규칙 적용)
- 안전 규칙: 같은 항목 하루 2회 초과 금지, 3일 연속 이탈 시 자동 복원 중지 후 알림, 야간 방해금지 복원 금지, 로밍 중 데이터 복원 금지, 한 점검당 시도 3회
- 에스컬레이션: 규칙 엔진 원문 → Liner 요약 → 텔레그램. 망이 끊기면 원문을 대기열에 두고 망 복구 시 재전송
- TTS 한 줄 안내(복원 전·후) + "지금 고치는 중" 표시와 큰 중단 버튼 (앱 상단 배너 + 접근성 오버레이)
- 증상 버튼 "폰이 이상해요" (Liner 분류 입력 지점; 분류 실패·`OTHER`면 일반 점검)
- 장애 주입 메뉴 (디버그 빌드 전용): 비행기 모드 켜기, 무음, 방해금지, 전화 앱 알림 끄기
- 데모용 임계값 단축 스위치 (장시간 통화 30분 ↔ 5분. **값 저장·표시만**, 통화 감지는 2단계)
- UI 2차 1부: 기록을 부모님용 요약 / 가족용 전체 로그로 분리(같은 문장 반복은 "(N번)"으로 묶음), 큰 타일 버튼, 짙은 파랑 주색·상태 3색·카드형 구역
- UI 2차 2부: 토스트 0개. 점검 결과는 결과 카드 1장으로 표시하고, [🔊 읽어 주기] 버튼으로 음성 안내. TalkBack이 켜져 있으면 자동 음성 대신 카드 liveRegion. TTS 엔진 `<queries>` 선언. 결과는 `result_note`에 저장
- 벨소리 복원: 방해금지 해제를 벨소리 복원보다 먼저 시도(일반 API 우선, 접근성 타일은 폴백). 화면이 꺼져 있으면 미룸으로 기록하고 잠금 해제 때 다시 고침
- 점검 후 앱 복귀: 접근성 복원이 연 시스템 화면이면 뒤로 가기로 앱으로 돌아오기 시도. 창 변화가 0.5초 멈출 때까지 기다린 뒤 판정하고, 홈 화면이면 앱을 한 번만 다시 연다 (뒤로 가기를 누른 뒤에 홈이 나왔을 때만). 2026-11-24 수정, 단위 테스트 통과

미구현(2·3단계): Shizuku, B등급 전체, 장시간 통화 감지·끊기, SMS 폴백, 블루투스/차단 목록/쉬운 사용 모드 복원.

## 안부 신호

- 하루 1회 09시 알람(`Scheduler.HEARTBEAT_HOUR`)에 "정상" 신호를 기존 `TelegramClient`로 현도에게 보냅니다. 메시지는 `[부모님 폰 안부 신호] 정상` + `보낸 시각`뿐이며, 설정값·메시지·통화 내용은 담지 않고 Liner도 거치지 않습니다.
- **지연 기준**: 예정 시각(09:00)보다 1시간 이상 늦게 보내지면 `정상 (지연됨)`으로 표시합니다 (Doze 오경보 구분용). 보낸 시각은 실제 전송 시각입니다.
- 하루 1회: 슬롯 날짜 단위로 한 번만 보냅니다 (`HeartbeatSender`, 날짜는 `Store`에 저장).
- 망이 끊기면 "보낼 차례" 상태가 남고, 망 복구·잠금 해제·다음 알람 때 한 통만 지연 표시로 나갑니다 (며칠 밀려도 쌓지 않습니다).
- **36시간 끊김 판단은 받는 쪽(현도)이 합니다.** 앱에는 서버 감시 기능이 없습니다. 36시간 넘게 안부 신호가 없으면 접근성 권한이 꺼졌거나 폰에 문제가 있는 것으로 보고 직접 확인하세요.
- **전제조건: 배터리 최적화 제외.** 설정 > 앱 > 폰 도우미 > 배터리 > **제한 없음**(또는 절전 예외 등록)으로 두어야 알람과 전송이 밀리지 않습니다. 접근성 서비스가 켜져 있어야 잠금 해제·망 복구 때 따라잡습니다.

## 구조

```
core/   순수 로직 (스냅샷·비교·복원 판정·이력·에스컬레이션 메시지)  ← 단위 테스트 대상
net/    Liner·텔레그램 클라이언트, 요청 본문 조립, 대기열, 전송 오케스트레이션
android/ 설정 읽기, 복원 수단, 접근성 서비스, 알람, TTS, 화면
```

조작 결정은 규칙 엔진(`RestorePolicy`)만 합니다. Liner는 증상 분류와 요약에만 씁니다.

## Liner API 사용처

Base URL `https://platform.liner.com/api/v1`, 모델 `liner-mark-1.0`, `Authorization: Bearer <키>`, `max_completion_tokens`, `reasoning_effort: none`. 429는 `Retry-After`를 지켜 최대 2회 재시도합니다.

1. 증상 분류 (`LinerClient.classify`): 부모님 말(최대 300자) → `SMS_NOT_RECEIVED`/`CALL_NOT_RECEIVED`/`CALL_NOT_MADE`/`CALL_NOT_ENDED`/`SLOW_APP`/`OTHER`
2. 에스컬레이션 요약 (`LinerClient.summarize`): 설정값·시도 내역·전후 수치 원문만 전송. 요약문에서 사람을 이름으로 부르지 않도록 지시

키가 없거나 망이 끊기면 호출하지 않고(또는 실패하면) 규칙 엔진 원문으로 동작합니다.

## 키·토큰 설정 (local.properties)

비밀값은 코드에 없습니다. `local.properties.example`을 `local.properties`로 복사해 채우세요 (`.gitignore` 처리됨, 커밋 금지).

```
sdk.dir=/path/to/android-sdk
liner.api.key=
telegram.bot.token=
telegram.chat.id=
```

비워 두어도 빌드와 단위 테스트는 됩니다. 값은 빌드 때 `BuildConfig`로 주입됩니다.

## 빌드·실행·테스트

```
export JAVA_HOME=~/jdk-21 PATH=$JAVA_HOME/bin:$PATH
export JAVA_TOOL_OPTIONS="-Djava.net.preferIPv6Addresses=true"   # 이 VM 샌드박스용
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest      # 단위 테스트
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

단위 테스트 316개 전부 통과 (2026-11-25 기준). APK 약 1.38MB.

설치 후 순서: 앱 정보에서 **제한된 설정 허용** → 접근성 서비스 켜기 → 알림 정책 접근 켜기 → 앱 실행해 동의 → 폰이 정상일 때 **기준 찍기**. (다른 앱 위에 표시 권한은 필요 없습니다. 중단 오버레이는 접근성 오버레이로 띄웁니다.)

## 위험

- **봇 토큰·API 키는 APK에 들어갑니다.** `BuildConfig`로 주입된 값은 APK에서 추출될 수 있습니다. 가족용 사이드로드 프로토타입 전제이며, 배포용 APK에는 이 키를 쓰지 말고 추출돼도 폐기 가능한 전용 봇·키를 쓰세요.
- 접근성 탭은 화면 문구(텍스트)로 요소를 찾습니다. One UI 버전·언어가 다르면 못 찾을 수 있고, 그 경우 복원 실패로 기록하고 에스컬레이션합니다.
- 주기 점검은 접근성 서비스가 켜져 있어 프로세스가 유지된다는 전제입니다. 삼성 절전 등록이 필요합니다.
