# 부모님 폰 AI 에이전트 — 정상 설정 스냅샷 + 자동 복원 설계

확정일: 2026-11-03 (현도 승인)
수정일: 2026-11-12 — ① 통화 기준 30분으로, 테스트 기기 Flip5로 변경 ② Opus 검증(2026-11-12) 지적 반영. Shizuku는 마지막 단계(3단계)에 사용하기로 확정해 원 설계를 유지한다. 단계 표기는 1단계/2단계/3단계로 통일했다.
대상: 부모님 사용 갤럭시 A (별도 거주, 연로, 스마트폰 조작 어려움)
테스트 기기: Galaxy Z Flip5 (One UI 9.0, Android 17) — 2026-11-12 현도 결정
전제: 새로 개발하는 가족용 사이드로드 앱. Play Store 배포 전제가 아님 (sms-forward와 동일 전제).
Liner API 사용: 조작 결정은 규칙 엔진만 하고, Liner 모델 API는 증상 분류와 에스컬레이션 요약에만 쓴다. 망이 끊겼을 때는 규칙 엔진만으로 동작한다 (§10·§11 참조).

## 1. 문제 정의 (현도 확인 사실)

- 주요 증상: 문자 안 옴, 전화 안 받아짐, 전화 안 됨, 상대가 안 끊으면 본인도 안 끊고 통화 계속 유지.
- 패턴: 대부분 기기를 잘못 만져 설정이 잘못 눌린 경우. 정 안 될 때는 껐다 켜면 정상으로 돌아온 경우도 있었음.
- 결론: 증상별 일반 진단보다, "정상 상태로 되돌리기"가 본체다.

## 2. 설계 원칙

1. **기준이 먼저다.** 정상 값은 하드코딩하지 않는다. 현도가 폰을 제대로 세팅한 상태에서 찍은 스냅샷이 기준이다.
2. **안내만으로 끝내지 않는다.** 에이전트는 직접 수정까지 시도한다. 부모님에게 단계를 따라오게 하지 않는다.
3. **반복하지 않는다.** 같은 수정은 한 증상당 1회만. 총 시도 3회까지, 그 다음은 에스컬레이션하고 멈춘다.
4. **되돌릴 수 있는 것부터.** 가벼운 설정부터, 위험한 것은 확인을 받거나 현도에게 넘긴다.
5. **부모님이 멈출 수 있다.** 수정 중에는 "지금 고치는 중" 표시 + 큰 중단 버튼을 항상 둔다.
6. **부모님 동의가 먼저다.** 설치할 때 부모님께 에이전트가 하는 일(무엇을 자동으로 되돌리는지, 어떻게 멈추는지)을 설명하고 동의를 받는다. 복원 기록은 부모님도 앱 안에서 볼 수 있게 한다.

## 3. 정상 스냅샷 (기준 항목)

설치 방문 시 현도가 폰을 정상 상태로 만든 뒤, 에이전트가 아래를 찍어 로컬에만 저장한다.
부모님별 실제 상태가 기준이므로, 아래는 항목 목록이지 고정값이 아니다.

- 네트워크: 비행기 모드 꺼짐, 와이파이 켜짐, 모바일 데이터 켜짐, SIM 인식됨
- 소리·알림: 벨소리 모드(무음 아님), 미디어·벨소리 볼륨 범위, 방해금지 꺼짐(야간 일정이 있으면 그 일정은 별도 기록), 전화·메시지 앱 알림 켜짐
- 전화·문자: 기본 전화 앱, 기본 문자 앱, 가족 번호 차단 없음, 스팸 차단 목록(가족 번호 없음)
- 디스플레이·접근성: 쉬운 사용 모드 켜짐, 글자 크기, 우발적 터치 방지 켜짐, 볼륨 올리기로 전화 받기 켜짐, 측면 버튼으로 통화 종료 켜짐
- 전원·유지: 자동 다시 시작 켜짐(요일·시간 기록), 배터리 최적화에서 에이전트 제외됨
- 에이전트 자체: 접근성, 알림 접근(필요 시), 시스템 설정 쓰기, 전화 권한(ANSWER_PHONE_CALLS) 상태
- 허용 블루투스 기기 목록: 보청기 등 항상 연결돼 있어야 하는 기기는 목록에 두고, 자동 복원이 건드리지 않는다.

저장하지 않는 것: 문자 내용, 통화 내용, 사진, 연락처 전체, 비밀번호·PIN. 스냅샷은 설정값과 마지막 수신·통화 시각(내용 제외) 수준까지만 둔다. 복원 기록은 부모님도 앱 안에서 볼 수 있게 남긴다.

### 설치 절차 (설치 방문 시 순서대로 확인한다)

1. 부모님 동의 절차 (§2 원칙 6)를 먼저 한다.
2. 사이드로드 설치 후 앱 정보에서 "제한된 설정 허용"을 먼저 누른다. Android 13부터 사이드로드 앱은 이걸 먼저 허용해야 접근성 서비스와 알림 접근을 켤 수 있다. SMS 권한이 제한 대상에 드는지는 Android 17에서 실측한다.
3. 접근성, 알림 접근, 다른 앱 위에 표시, 알림 정책 접근, 시스템 설정 쓰기, 전화 권한을 사용자가 설정 화면에서 직접 켠다.
4. 배터리 최적화에서 에이전트를 제외하고, 삼성 "절전 안 함 앱"에도 등록한다. 삼성은 표준 Doze와 별개로 "절전 앱 / 깊은 절전 앱" 자동 분류가 있어, 등록하지 않으면 주기 점검과 심박이 끊긴다.
5. 부모님 폰의 금융 앱(은행·간편결제·모바일 신분증)을 실행해 본다. 개발자 옵션·무선 디버깅이 켜져 있으면 실행을 거부하는 앱이 있어, 충돌하면 Shizuku를 쓰지 않는 구성을 기본으로 둔다.
6. 삼성 자동 차단(Auto Blocker) 상태를 확인한다. 켜져 있으면 사이드로드와 USB 명령이 막힌다. 끄는 것은 보안을 낮추는 결정이라 설치 절차에 위험 고지를 넣는다.
7. Google의 사이드로드 개발자 인증 요구가 일정·국가에 따라 적용될 수 있다. ADB 설치가 예외인지는 제출 전에 확인한다.

## 4. 감지 (언제 비교하나)

- 주기 점검: 하루 2회(아침·저녁) + 잠금 해제 후 첫 1회 수준으로 가볍게. 배터리 부담을 주지 않는다.
- 증상 버튼: 부모님이 "문자 안 와요 / 전화 안 돼요 / 느려요" 버튼을 누르면 즉시 비교.
- 통화·문자 이상 감지: 부재중 통화 기록이 있거나 부모님이 증상 버튼을 누르면 점검한다. 폰 스스로 오지 않은 문자를 알 수는 없으므로 "수신 시각이 기준과 어긋나면"으로는 감지하지 않는다. 장시간 통화 감지(30분)는 2단계 기능이라 1단계에서는 통화 중 감지를 하지 않는다.
- 에이전트 심박: 하루 1회 "정상" 신호를 현도에게 보낸다. 신호가 36시간 끊기면 에이전트 권한이 꺼졌거나 폰에 문제가 있는 것으로 보고 현도가 직접 확인한다. Doze 때문에 전송이 지연돼 오경보가 날 수 있으므로, 지연된 심박은 "지연됨"으로 구분해 표시한다. "잠금 해제 후 첫 1회"에 쓰는 ACTION_USER_PRESENT는 매니페스트로 받을 수 없으므로, 접근성 서비스처럼 상주하는 프로세스에서 받는다.

## 5. 자동 복원 등급

자동 복원 공통 안전 규칙: 같은 항목의 자동 복원이 하루에 2회를 넘으면 그날은 더 이상 되돌리지 않고 현도에게 알린다. **단, "지금 점검하기" 수동 점검은 이 2회 제한과 점검당 3회 제한을 적용하지 않으며, 수동 복원은 일일 횟수에도 세지 않는다** (2026-11-14 실기에서 수동 테스트가 제한에 걸려 추가). 같은 이탈이 3일 연속 반복되면 의도된 변경으로 보고 자동 복원을 멈추고 현도에게 묻는다. 야간 시간대(부모님 취침 시간, 스냅샷에 기록)에는 방해금지 복원을 하지 않는다. 해외 로밍 중에는 모바일 데이터 복원을 하지 않는다.

### A등급 — 사전 승인, 자동 복원 (부모님 확인 없이, 복원 후 음성 한 줄 안내)
- 무음 해제, 벨소리·볼륨을 기준 범위로 복원 (일반 API)
- 전화·메시지 앱 알림 켜짐으로 복원 (일반 API; 알림 정책 접근은 설치 시 사용자가 미리 켜둠)
- 방해금지 해제 (1단계에서는 접근성 탭으로 설정 화면에서 끈다. 야간 시간대에는 복원하지 않는다. 일반 API로는 Android 15부터 targetSdk 35 이상 앱이 자기 앱 규칙만 끌 수 있어, 사용자가 직접 켠 방해금지는 끌 수 없을 수 있다 — Flip5에서 실측한다. Shizuku 경로는 3단계에서 쓴다.)
- 비행기 모드 꺼짐으로 복원 (1단계에서는 접근성 빠른 설정 탭으로 끈다. 일반 앱은 Android 4.2부터 비행기 모드를 끌 수 없다. 부모님이 비행·병원 등 일부러 켠 경우를 구분할 수 없으므로, 복원했다는 음성 안내를 반드시 하고 같은 이탈이 반복되면 현도에게 묻는다.)
- 와이파이·데이터 켜짐으로 복원 (1단계에서는 접근성 탭으로 켠다. targetSdk 29 이상이면 `setWifiEnabled`가 동작하지 않고, 모바일 데이터는 공개 API가 아예 없다. 로밍 중에는 데이터 복원을 하지 않는다.)
- 1단계에서 A등급에서 뺀 것: 블루투스→스피커 전환(일반 전화 통화의 오디오 경로는 기본 전화 앱만 바꿀 수 있고, 보청기 사용자에게는 통화가 안 들리게 될 수 있다), 가족 번호 차단 자동 해제(기본 전화·문자 앱만 차단 목록을 읽고 쓸 수 있고, 삼성 전화·메시지 앱은 차단 목록을 따로 둔다), 쉬운 사용 모드·우발적 터치 방지 복원(삼성 전용 설정 키라 일반 API로 바꿀 수 없다). 이 세 가지는 1단계에서 빼고, 3단계에서 접근성·Shizuku 경로로 다시 검토한다.

### B등급 — 두 단계 확인 후 실행
- 확인 방법: 음성 확인 + 큰 버튼 탭의 두 단계를 거친다. 예를 들어 재부팅은 "다시 시작할까요?"라고 물은 뒤 부모님이 "다시 시작"이라고 말하거나 큰 버튼을 눌러야 실행한다. 한국어 "네?"는 되묻는 말과 억양이 같아 오인식 위험이 있어, "네" 한 마디만으로는 실행하지 않는다. 정해진 시간 안에 응답이 없으면 취소로 처리한다.
- 특정 앱 강제 종료 (후 재실행 필수. 강제 종료된 앱은 다시 실행될 때까지 푸시를 받지 못하므로, 메시지 앱을 강제 종료하면 "문자 안 옴" 증상을 에이전트가 직접 만든다.)
- 특정 앱 캐시 정리(데이터 삭제 아님. `pm clear --cache-only` 지원 여부는 실기에서 확인하고, 셸 명령은 화이트리스트로 고정한다. `pm trim-caches`는 전체 앱 캐시를 정리하는 명령이라 특정 앱 정리에는 쓰지 않는다.)
- 재부팅(전원 메뉴에서 다시 시작)

### C등급 — 자동 복원 금지, 현도에게 에스컬레이션
- 공장 초기화, PIN·비밀번호·생체 변경, 권한 회수, 사진·메시지 삭제
- 데이터 삭제(`pm clear` 수준), 기본 앱 변경 중 가족 외 앱으로의 변경
- 가족 외 번호 차단 해제, 통신사 스팸 차단 서비스 관련
- SIM·통신사·요금제 문제, 하드웨어 의심(배터리 부풀음, 화면·스피커 고장 등)
- 네트워크 설정 초기화 (Wi-Fi 비밀번호뿐 아니라 블루투스 페어링(보청기 포함)과 모바일 네트워크 설정까지 지운다. 부모님은 Wi-Fi 비밀번호를 다시 넣을 수 없으므로, 음성 "네" 한 번으로 실행할 조치가 아니다.)
- 사용하지 않는 앱 삭제 (카카오톡 대화 같은 데이터가 사라져 복구할 수 없다. "되돌릴 수 있는 것부터"라는 원칙과도 어긋난다.)

## 6. 수정 사다리 (증상별 순서)

공통 순서: 기준 변경 복원 → 앱 단위 조치 → 재부팅 → 재확인 → 에스컬레이션

- 문자 안 옴: 문자함 수신 여부 확인(왔는데 알림만 없음 vs 아예 없음 구분. 문자함 확인에는 READ_SMS가 필요하고, 이 권한은 문자 본문에도 접근할 수 있으므로 날짜·발신 번호만 읽는다는 것을 코드 수준으로 제한한다.) → 방해금지·알림 복원 → 차단 목록 확인 → 통신사 스팸 서비스 의심 시 에스컬레이션
- 전화 안 받아짐: 부재중 기록 확인 → 방해금지·벨소리·블루투스 복원 → 차단 목록 확인 → 받기 제스처를 한 번 터치로, 볼륨받기·전원끊기 설정 확인
- 전화 안 됨: 비행기 모드·신호·SIM 확인 → 비행기 모드 껐다 켜기 → 네트워크 설정 초기화는 C등급이라 현도에게 넘긴다 → 그래도 안 되면 에스컬레이션
- 통화 안 끊김: 예방 설정(볼륨받기·전원끊기)이 기준에 포함돼 있는지 먼저 확인 → 장시간 통화(30분) 감지 시 통화 중에는 화면이 꺼져 있고(근접 센서) 마이크가 점유돼 있어 큰 끊기 버튼도 음성 확인도 사실상 안 된다. 통화 중 TTS가 어디로 나가는지, 상대방에게도 들리는지는 실측이 필요하다. 그래서 2단계에서는 통화를 직접 끊지 않고, 통화가 끝난 뒤 부모님께 알리고 현도에게 통지하는 것까지만 한다. 끊기가 필요하면 접근성 탭 → TelecomManager.endCall 순서로 시도한다. `TelecomManager.endCall`은 API 29부터 지원 중단이라 기기에 따라 false를 반환할 수 있다. Shizuku가 있는 3단계에서는 `input keyevent KEYCODE_ENDCALL`을 1순위로 실측한다. 가족 번호(현도 포함)와의 통화는 끊기 확인 대상에서 제외한다. 부모님 확인 없이 장시간 통화를 멋대로 끊지 않는다. 데모용으로는 임계값을 단축하는 디버그 설정을 둔다 (30분 통화를 5분 데모에 보여줄 수 없으므로).
- 느려짐·앱 오류: 기준 변경 복원 → 문제 앱 강제 종료·캐시 정리(후 재실행 필수) → 재부팅 → 재확인

## 7. 재부팅 위치와 주의

- 재부팅은 첫 수단이 아니다. 방해금지·차단처럼 재부팅해도 남는 설정부터 복원한다.
- 재부팅이 유효한 경우: 멈춘 앱, 네트워크 스택, 오디오 경로 등 일시적 상태 꼬임.
- 재부팅 후에는 기준을 다시 확인한다. 재부팅으로 풀리는 설정과 남는 설정을 구분해 로그에 남긴다.
- 부모님 본인의 재부팅과 자동 다시 시작은 에이전트가 통제할 수 없다. Shizuku를 쓰는 3단계에서는 전체 재부팅 뒤에 Shizuku가 보통 살아남지 못하므로, 재부팅 뒤에는 에이전트가 일반 API·접근성 단계로 떨어지고, 현도에게 "Shizuku 재활성화 필요"를 알린다. 그래서 재부팅은 마지막 수단으로 둔다. 3단계에서는 설치 시 Shizuku나 ADB로 `WRITE_SECURE_SETTINGS` 영구 권한을 주는 방안도 검토한다. 이 권한은 재부팅 뒤에도 유지되지만, 비행기 모드처럼 보호된 브로드캐스트가 필요한 항목은 이 권한만으로 안 될 수 있어 실측이 필요하다.

## 8. 직접 수정 수단 (3단계)

1. 일반 API: 볼륨, 밝기·화면 꺼짐(시스템 설정 쓰기), 설정 패널 열기, 디바이스 케어 최적화 연결. 방해금지 해제는 일반 API로 안 될 수 있다(Android 15부터 targetSdk 35 이상 앱은 자기 앱 규칙만 끌 수 있음 — Flip5에서 실측한다). 1단계에서는 접근성 탭으로 대신한다.
2. 접근성 탭: Galaxy Z Flip5(One UI 9.0) 하나만 타깃으로 테스트한다. 화면 요소는 좌표가 아니라 텍스트·뷰 ID로 찾고, 찾지 못하면 바로 중단하고 에스컬레이션한다. Flip5는 폴더블이라 접었을 때와 펼쳤을 때 화면이 다르고 커버 화면도 따로 있어, 부모님 폰(바 형태 갤럭시 A)과 화면 구성이 다르다. 쉬운 사용 모드와 큰 글자 설정은 설정 화면 배치 자체를 바꾼다. One UI 버전별 매핑 표는 부모님 기종을 확인한 뒤에 만든다. 갤럭시 A 저가형은 백그라운드 프로세스를 더 공격적으로 종료할 수 있어, Flip5에서 통과해도 갤럭시 A에서 통과한다는 보장이 없다. 설정 화면 조작, 특정 앱 캐시·강제 종료 화면 진입, 전원 메뉴 다시 시작에 쓴다.
3. Shizuku(3단계, 마지막 단계): 루트 없이 ADB 권한으로 `am force-stop`, `settings put/get`, `pm trim-caches` 등. `pm clear`(데이터 삭제)는 C등급이라 쓰지 않는다. 셸 명령은 화이트리스트로 고정한다. Shizuku는 방문 시 무선 디버깅 또는 PC 연결로 1회 활성화한다. 무선 디버깅으로 부팅 후 자동 시작하는 기능이 최신 Shizuku에 있는지는 실측해야 하며, 있더라도 Wi-Fi 연결이 필수다. 개발자 옵션·무선 디버깅을 상시 켜 두면 국내 은행·간편결제·모바일 신분증 앱 상당수가 실행을 거부하므로, 설치 방문 때 금융 앱 실행 테스트를 하고 충돌하면 Shizuku를 쓰지 않는 구성을 기본으로 둔다.

## 9. 에스컬레이션 메시지 (현도에게 보내는 내용)

채널: 1순위 텔레그램(sms-forward의 봇 방식과 동일하게 봇 토큰 + 챗 ID), 데이터가 안 될 때는 SMS로 축약본 전송. SMS 폴백 구현은 2단계로 미룬다. 텔레그램 성공 경로가 먼저다.
메시지 본문은 규칙 엔진이 만들고, Liner 모델 API가 현도가 읽기 쉬운 한국어로 요약한다. 보내는 데이터는 설정값·시도 내역·전후 수치뿐이다. 망이 끊겼을 때는 요약 없이 원문을 대기열에 넣고, 망 복구 후 다시 보낸다. 비행기 모드나 SIM 문제처럼 망이 끊긴 상황에서는 텔레그램도 SMS 폴백도 나가지 않으므로, 망 복구 후 다시 보내는 대기열이 필요하다.
포함 항목: 증상, 시도한 수정(최대 3개)과 전후 수치, 기준에서 벗어났던 항목, 재부팅 여부, 남은 증상, 부모님 응답(2단계부터; 1단계에서는 응답을 받는 경로가 없으므로 해당 없음). "안 돼요" 한 줄로 보내지 않는다.
부모님에게는 동시에 음성으로 "아들한테 연락했어요, 잠시만 기다려요"라고 안내한다.

## 10. 범위 밖 (하지 않는 것)

- MDM 등록, 기기 소유자(Device Owner) 전환, 공장 초기화
- 자동 전화 받기, 부모님 확인 없는 통화 종료, 사진·메시지 삭제
- 뱅킹·결제 앱 조작, 비밀번호·계정 변경
- 문자·통화 내용, 사진, 화면 스크린샷을 클라우드 LLM으로 전송하는 것
- 단, 증상 발화 텍스트(부모님 말을 텍스트로 바꾼 결과)와 설정값·시도 내역은 Liner 모델 API로 보낼 수 있다. 조작 결정은 규칙 엔진만 하고, LLM은 증상 분류와 에스컬레이션 요약만 맡는다. 망이 끊겼을 때는 Liner를 쓸 수 없으므로 규칙 엔진만으로 동작한다.

## 11. 단계별 구현 순서

- 1단계: 기준 스냅샷 찍기 + 주기 비교 화면 + 실현 가능한 A등급 자동 복원(무음·볼륨·알림·방해금지·비행기 모드·Wi-Fi·데이터, 각각 §5의 안전 조건 포함) + 에스컬레이션 메시지(텔레그램 + Liner 요약) + TTS 한 줄 안내 + 중단 버튼 + 증상 버튼 1개(Liner 분류 입력 지점) + 장애 주입 메뉴 + 비밀값 분리. Shizuku 제외. LLM은 조작 결정에 쓰지 않는다(규칙 기반; Liner는 증상 분류·요약만). SMS 폴백은 2단계로 미룬다.
- 2단계: 증상 버튼 확대 + 음성 안내 + B등급 확인 흐름(두 단계 확인) + 장시간 통화 감지·알림(끊기는 시도하지 않고 통지까지만; 가족 번호 제외) + SMS 폴백.
- 3단계: Shizuku 연동(강제 종료·캐시 정리·보안 설정) + 심박·복원 로그 대시보드(현도용 요약) + 접근성 One UI 버전별 매핑(부모님 기종 확인 뒤).

데모 요건(1단계에 포함): 장애 주입 메뉴로 고장을 버튼 하나로 재현한다(비행기 모드 켜기, 무음, 방해금지, 알림 끄기). 30분 통화는 디버그 임계값 단축 설정으로 보여준다. 봇 토큰과 챗 ID는 소스에서 빼 local.properties나 빌드 변수로 분리한다. 가족 전화번호와 스냅샷 예시 데이터는 커밋하지 않는다. 앱에 박힌 봇 토큰은 APK에서 추출될 수 있다는 점을 기획서 위험 항목에 적는다.

## 12. 테스트 시나리오 (실기, Galaxy Z Flip5)

1단계: 비행기 모드 켜짐, 방해금지 켜짐, 와이파이 꺼짐, 볼륨 0, 메시지 알림 꺼짐, 재부팅 후 기준 재확인, 에이전트 권한 꺼짐 시 심박 중단, Liner 요약 에스컬레이션 수신, 장애 주입 메뉴 동작. 각 시나리오는 수정 전후 수치와 로그를 남긴다.
2단계: 30분 통화 알림·현도 통지, 디버그 임계값 단축(데모용), B등급 두 단계 확인, SMS 폴백, 전화 앱 강제 종료 후 재실행.
3단계: Shizuku 경로 강제 종료·캐시 정리, 재부팅 뒤 Shizuku 소실·재활성화, 접근성 One UI 버전별 매핑(부모님 기종 확인 뒤), 가족 번호 차단(1단계 수단으로는 불가능해 3단계에서 접근성·Shizuku 경로로 검토).
데모 촬영용으로는 장애 주입 메뉴로 고장을 재현하고, 30분 통화는 디버그 임계값 단축으로 보여준다.
