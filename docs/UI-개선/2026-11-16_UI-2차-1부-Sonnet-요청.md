## 구현 범위 (2차 1부 — 계획서 1부 §1~§3 그대로)
1. **P7 기록 분리 (LogEntry에 kind + parentText)**:
   - `LogKind` enum: FIXED, FAILED, INFO, DEV. JSON 키는 기존 `t`/`x` 유지 + `k`(kind 이름 문자열)와 `p`(parentText) 추가.
   - **주의: 계획서 §2 "새 파일"에 `core/LogKind.kt`가 두 번 나와 있다. 파일은 하나만 만들고, code 기반 enum(`FIXED("f")`, `FAILED("x")`, `INFO("i")`, `DEV("d")`) + `fromCode`로 통일할 것.**
   - 호환 규칙: `k`가 없거나 알 수 없는 값이면 DEV, `p`가 없거나 빈 문자열이면 null. 예전 기록은 부모님 영역에 안 나오고 관리 영역에만 남는다 (의도된 동작).
   - 부모님 영역: FIXED/FAILED 항상 표시, INFO는 parentText 있을 때만, DEV 표시 안 함. 줄 형식 `{기호} {시각 문구} — {parentText}`, 기호 FIXED `✓` FAILED `✕` INFO `•`. 시각 문구: 오늘 "오늘 오후 3:10", 어제 "어제 오전 9:05", 그 이전 "5월 3일 오후 3:10". 문장은 존댓말 "~했어요"체, 기술 용어·숫자·괄호 금지. 가족 알림 문구(". 가족에게 알렸어요")는 알림을 실제로 보냈을 때만 붙이고, 못 보냈으면 ". 가족에게 전화해 주세요". 횟수 제한 차단은 FAILED로 분류. 기준 찍기·멈춤 해제·QUEUED·진단은 DEV. 표시 건수는 묶은 뒤 최근 5건, 빈 상태 문구 "아직 고친 일이 없어요".
   - 관리 영역: 전체 20건을 원문(`text`) 그대로 최신순, 기본은 접힌 상태(기존 `collapsible` 사용).
2. **P8 표시할 때만 연속 반복 묶기**: 저장은 바꾸지 않고 표시할 때만 바로 이어지는 같은 기록을 묶는다. 부모님 영역은 kind+parentText 기준, 관리 영역은 text 기준. 묶은 줄은 가장 최근 시각 + " (N번)" (1번이면 안 붙임). 묶은 뒤에 5건으로 자른다.
3. **P25 색 정리**: 주색 짙은 파랑 `#1565C0` 유지 (주황은 노랑·빨강 상태색과 혼동 위험). 팔레트: 주 동작 `#1565C0`+흰 글씨(타일 2개·확인 버튼), 정상 `#2E7D32`(상태 카드만), 주의 `#F9A825`+검은 글씨(상태 카드만), 위험 `#C62828`(상태 카드와 [중단]만), 보조 흰 바탕+`#424242` 글씨+`#9E9E9E` 1dp 테두리(관리·가족 영역 모든 버튼), 카드 흰 바탕 `#FFFFFF`+테두리 `#E0E0E0`, 화면 바탕 `#F5F5F5`. 보라·초록 버튼은 없애고 보조 버튼으로.
4. **P12 큰 타일 버튼**: `Ui.button`에 크기 인자 추가 대신 계획서대로 `Ui.tile(ctx, icon, title, sub, onClick)`을 새로 만든다. minHeight 112dp(고정 높이 아님), 가로 MATCH_PARENT, 모서리 20dp, 간격 16dp, 아이콘 32sp, 제목 27sp 굵게, 보조 20sp. 버튼 2개: [🔍 지금 점검하기 / 설정이 괜찮은지 봐요], [🆘 폰이 이상해요 / 가족에게 바로 알려요]. 세로로 하나씩 전체 폭. **`bigButton`(104dp)은 삭제하고 호출하는 곳도 전부 `tile`로 바꾼다.**
5. **P26 구역 카드**: 상태 카드 아래 구역을 각각 `Ui.card()`로 감싼다 (타일 묶음, 최근 고친 일, 취침 시간, 가족, 관리). `card()` 기본값: 모서리 16dp, 테두리 1dp `#E0E0E0`, 안쪽 여백 16dp, 카드 간격 12dp. 접힘 영역(가족·관리)은 카드 안에 `collapsible`을 넣는다.

## 파일별 변경 (계획서 1부 §2)
- **새 파일**: `core/LogKind.kt` (enum + fromCode), `core/LogPresentation.kt` (순수 함수: `collapseRepeats`, `formatCount`, `parentVisible`, `parentRows(limit=5, 묶은 뒤 자르기)`, `kindSymbol`, `LogRow` 데이터 클래스).
- **고치는 파일**: `Store.kt` (LogEntry 필드 추가 + toJson/fromJson + `addLog(text, kind, parentText)` 시그니처 확장, 기본값으로 기존 호출 유지), `CheckRunner.kt` (고친 경우 FIXED+부모님 문구, 못 고친 경우 FAILED+부모님 문구, 이상 없음 INFO+parentText "점검했어요, 문제 없어요", 진단 문자열은 DEV 유지, 부모님 문구는 `private fun parentMessage(result)` 한 곳에 모으기), `Ui.kt` (색 상수 + `tile` + `card` + `statusBadge` + `manageButton` + `logRowView` + `bigButton` 삭제), `MainActivity.kt` (구역별 `Ui.card`로 재구성, `bigButton` 호출 전부 `tile`로 교체, `renderParentLog()`는 `parentRows(store.logs(), 5)` 사용, 개발자 로그는 `collapseRepeats`만 적용해 DEV 포함 표시, 상태 표시는 `statusBadge` 사용), `res/values/colors.xml`·`themes.xml`(사용하는 경우 `colorPrimary`를 `#1565C0`으로).
- **주의**: `Store.kt`의 `fromJson`이 모르는 키를 무시하는지 구현 전에 확인할 것 (계획서 §4 되돌리기 참고). 예전 APK로 새 JSON을 읽는 동작은 밀리가 따로 확인한다.

## 구현 방식
- **코드 기반 View 유지, Compose·XML 전환 금지.** 1차에서 만든 `Ui.card()`·`Ui.collapsible()`·`Ui.statusCard()` 등은 재사용하고, 새로 필요한 것만 추가한다.
- 등급 계산·기록 표시 규칙은 Android 없는 순수 함수로 `core/`에 두고 단위 테스트를 붙일 것 (1차의 StatusCard 방식과 동일).
- 기존 기능은 전부 유지: 동의 다이얼로그, 고치는 중 배너 + [중단] 버튼, 스냅샷 찍기/표시, 멈춘 항목 다시 켜기, 지금 점검하기, 폰이 이상해요(Liner 분류), 고친 기록, 대기열 다시 보내기, 데모 스위치·통화 기준, DEBUG 장애 주입 메뉴, Liner/텔레그램 키 상태 줄, 안부 신호(09:00).
- 2부(P19 결과 카드·P20 읽어 주기·토스트 0개)는 **이번에 하지 않는다.** 토스트는 건드리지 말 것.
