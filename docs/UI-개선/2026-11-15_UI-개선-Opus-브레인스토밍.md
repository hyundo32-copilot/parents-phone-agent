# 폰 도우미 UI 개선 브레인스토밍 (Opus 5.5, 2026-11-15)

> 이번 라운드는 아이디어만 냅니다. 코드는 읽기만 했고 고치지 않았습니다.
> 읽은 파일: `android/MainActivity.kt`, `android/Ui.kt`, `android/StatusBus.kt`, `android/Announcer.kt`, `android/AgentAccessibilityService.kt`(오버레이 부분), `android/CheckRunner.kt`(로그 문구), `core/SettingKey.kt`, `android/Store.kt`(LogEntry), 그리고 `2026-11-14_Flip5-실기-결과.md`.

## 1. 배경

- 앱: 폰 도우미 (`com.hyundo.parentsagent`). 부모님 폰 설정이 잘못 바뀌면 기준 상태로 자동 복원한다. 라이너 .EXE-THON 출품작, 1단계 프로토타입.
- 전제: **한 화면(MainActivity) 하나에 모든 정보를 둔다.** 화면을 나누지 않는다.
- 사용자가 두 부류다.
  - 부모님: 큰 글씨·큰 버튼이 필요하다. "지금 괜찮은지"와 "뭘 누르면 되는지"만 알면 된다.
  - 현도: 평소에는 텔레그램으로 보고, 가끔 Flip5 실기에서 진단 정보(복원 수단, 실패 사유, 키 상태)를 본다.

## 2. 현재 화면 요약과 문제점

| 순서 | 섹션 | 지금 모습 | 문제 |
|---|---|---|---|
| 0 | 고치는 중 배너 | 노란 배경, 24sp 문구, 빨간 [중단] 96dp | 괜찮음. 다만 스크롤 영역 밖 상단 고정이라 좋은데, 앱 화면에서는 진행 정도(몇 번째 항목인지)가 안 보임 |
| 1 | 제목·부제 | 30sp / 20sp | 화면 맨 위 한 줄을 차지하지만 정보가 없음 |
| 2 | 준비 상태 | ✔/✘ 텍스트 + 설정 버튼 2~3개 | 부모님은 "접근성 서비스", "알림 정책 접근"이라는 말을 모름. ✔/✘가 작은 글자 기호라 색 구분도 없음 |
| 3 | 기준 상태 | 찍은 시각·취침 시간·10개 항목 값을 18sp 텍스트 덩어리로 | 화면 위쪽을 크게 차지함. 부모님에게는 의미 없는 정보가 가장 좋은 자리에 있음. [기준 찍기]는 부모님이 잘못 누르면 "고장난 상태"를 기준으로 굳혀 버리는 위험 버튼인데 파란 기본 버튼으로 가장 먼저 나옴 |
| 4 | 자동 복원 멈춘 항목 | 초록 버튼 | "같은 이탈이 3일 연속 반복"은 현도용 문장 |
| 5 | 점검 | [지금 점검하기] 파랑, [폰이 이상해요] 주황 | **부모님이 실제로 누를 버튼이 스크롤 아래에 묻힘.** 기준 목록 10줄 뒤에 나와서 Flip5 메인 화면에서도 첫 화면에 안 보일 가능성이 큼 |
| 6 | 고친 기록 | 최근 20줄, "M월 d일 HH:mm 내용" | 내용이 `비행기 모드: 켜짐 → 꺼짐 (성공) — 설정 화면`, `현도에게 알림: QUEUED`, 진단 문구("문구 N곳 발견, 스위치 M개")처럼 개발자 문장이 섞임. 같은 문장 반복(실기에서 "이미 2회라…" 4번 반복)도 그대로 4줄 |
| 7 | 대기열 | "아직 못 보낸 알림 N건" + 회색 버튼 | 현도용 |
| 8 | 데모 설정 | 스위치, 통화 기준 문구, (DEBUG) 장애 주입 보라 버튼, 키 상태 14sp | 전부 현도·심사용. 부모님이 데모 스위치를 실수로 바꿀 수 있음 |

핵심 문제 세 가지로 줄이면:

1. **"지금 폰이 괜찮은지"를 한 번에 알려 주는 곳이 없다.** 상태가 준비 상태·기준·기록에 흩어져 있다.
2. **부모님이 누를 버튼(점검·이상해요)이 화면 중간 아래에 묻혀 있고, 위험한 버튼(기준 찍기)과 개발용 요소가 더 좋은 자리에 있다.**
3. **부모님용 문장과 현도용 문장이 한 목록에 섞여 있다.** 버튼 색도 5가지라 색이 뜻을 갖지 못한다.

## 3. 제안 목록

난이도: 소 = 반나절 안, 기존 코드 순서 바꾸기·문구 바꾸기 수준 / 중 = 하루 안팎, 작은 상태 계산이나 새 뷰 도우미 필요 / 대 = 구조 변경·여러 파일·실기 반복 확인 필요.

### 3.1 정보 위계 (섹션 순서·강조)

**P1. 섹션 순서를 "부모님 영역 → 현도 영역" 2단으로 다시 배치** — 난이도 소
- 새 순서:
  1. (고치는 중 배너 — 지금처럼 상단 고정)
  2. **상태 카드** (3.2의 P4)
  3. **큰 버튼 2개**: [지금 점검하기], [폰이 이상해요]
  4. 할 일이 있을 때만 나오는 안내 카드: 준비 안 됨(권한), 기준 없음, 멈춘 항목
  5. 최근 고친 일 (부모님용 요약 3~5줄, 3.3의 P7)
  6. ── 구분선 "가족·관리용" ──
  7. 기준 상태 상세 + [기준 찍기]
  8. 전체 기록(현도용, 접힘)
  9. 대기열, 데모 설정, 장애 주입, 키 상태 (접힘)
- 왜: 화면을 켜자마자 보이는 첫 화면(스크롤 없이 보이는 부분)에 "괜찮은지 + 누를 버튼"만 있게 된다. 지금 `render()`가 순서대로 `addView`하는 구조라 순서만 바꾸면 되므로 거의 공짜다.
- 주의: 제목 "폰 도우미"는 상태 카드 안의 작은 머리글로 넣거나 아예 빼도 된다. 앱 이름은 이미 아이콘·상단에 있다.

**P2. 권한이 꺼져 있으면 그 안내가 상태 카드 바로 아래 최우선으로** — 난이도 소
- 접근성이 꺼지면 앱이 사실상 못 고친다. 이때는 "준비가 덜 됐어요. 가족에게 보여 주세요" + 설정 버튼을 상단 카드에 올린다. 켜져 있으면 준비 상태 섹션은 통째로 숨기고, 아래 관리 영역에 "✔ 접근성 켜짐 · ✔ 알림 정책 켜짐" 한 줄만 남긴다.
- 왜: 정상일 때 쓸모없는 줄 2개가 사라지고, 비정상일 때는 가장 눈에 띈다. 정보는 그대로 다 있다(전제 유지).

**P3. [기준 찍기]를 관리 영역으로 내리고 한 번 더 확인** — 난이도 소
- 지금 다이얼로그가 이미 확인 역할을 하지만, 버튼 자체가 부모님 영역 위쪽에 있다. 관리 영역으로 내리고 버튼 문구를 "기준 다시 찍기 (가족이 할 일)"로 바꾼다.
- 왜: 부모님이 폰이 이상한 상태에서 이 버튼을 누르면 이상한 상태가 정상으로 굳는다. 앱의 안전 전제를 깨는 유일한 부모님 손 닿는 버튼이다.

### 3.2 상태 한눈에 보기

**P4. 맨 위 큰 상태 카드 1장 (초록/노랑/빨강 3단계)** — 난이도 중 · **가장 효과 큼**
- 모양: 가로 전체, 둥근 모서리, 큰 아이콘(✓ / ! / ✕, 48~64sp 또는 벡터) + 굵은 한 줄 + 보조 한 줄.
  - 🟢 정상: "폰이 괜찮아요" / "마지막 확인: 오늘 오후 3:10"
  - 🟡 주의: "확인이 필요해요" / 예: "자동으로 못 고친 게 있어요. 가족에게 알렸어요" 또는 "준비가 덜 됐어요"
  - 🔴 문제: "고치지 못했어요" / "가족에게 연락했어요" (또는 텔레그램 대기 중이면 "연락을 아직 못 보냈어요")
  - (고치는 중일 때는 기존 노란 배너가 우선)
- 상태를 정하는 규칙(새로 계산 필요, 이게 '중'인 이유):
  - 빨강: 마지막 점검 결과에 FAILED가 있음
  - 노랑: 권한 꺼짐 / 기준 없음 / 멈춘 항목 있음 / 마지막 점검이 오래됨(예: 24시간) / 대기열에 못 보낸 알림
  - 초록: 위 어느 것도 아님
- 구현 메모: 지금 `CheckOutcome.Done(summary)`는 문자열만 남기고 화면은 토스트로 띄우고 끝난다. **마지막 점검의 시각·결과 등급을 Store에 한 줄 저장**해야 카드가 앱을 다시 켜도 맞는 상태를 보여 준다. 화면을 열 때 `reader.readAll(deep=false)`로 기준과 바로 비교하는 방법도 있지만, 메인 스레드에서 읽기·접근성 호출이 섞일 수 있으니 "마지막 점검 결과 저장" 쪽을 권한다.
- 왜: 부모님 질문 1번 "내 폰 괜찮아?"에 화면이 한 번에 답한다. 현도도 실기에서 카드 색만 보면 된다. 심사 데모에서도 "빨강 → 점검 → 초록"으로 바뀌는 장면이 가장 설명력이 크다.

**P5. 기준 상태 목록을 "항목 칩/표"로** — 난이도 중
- 지금 `"비행기 모드: 꺼짐\n와이파이: 켜짐…"` 18sp 텍스트 덩어리를, 항목마다 한 줄씩 [이름 | 기준값 | (마지막 점검 때) 현재값 ✓/✕] 형태로. 다른 항목만 빨간 글씨.
- 왜: 현도가 실기에서 "어떤 항목이 지금 다르냐"를 바로 본다. 부모님 영역이 아니라 관리 영역이므로 색 남용 걱정은 적다.
- 과한 부분: 항목마다 아이콘(비행기·와이파이 그림)까지 넣는 건 1단계에 과하다. 텍스트+✓/✕로 충분.

**P6. ✔/✘ 기호를 색 있는 큰 기호로** — 난이도 소
- 남겨 두는 줄(권한 상태 등)은 ✔를 초록, ✘를 빨강으로 칠하고(`SpannableString` 또는 TextView 두 개), 글로 "켜짐/꺼짐"을 같이 쓴다. 색맹 대비를 위해 색만으로 뜻을 전하지 않는다.

### 3.3 고친 기록

**P7. 기록을 "부모님용 요약"과 "현도용 전체 로그"로 나누기** — 난이도 중
- 부모님이 볼 것: "무엇을 / 고쳤는지 못 고쳤는지"뿐. 예:
  - ✓ 오늘 오후 3:10 — 와이파이를 다시 켰어요
  - ✕ 오늘 오후 3:10 — 비행기 모드를 못 고쳤어요. 가족에게 알렸어요
- 현도가 볼 것: 지금 로그 그대로(전·후 값, 복원 수단, 진단 문구, `QUEUED` 같은 상태값, 기준 찍기·멈춤 해제 같은 이벤트).
- 구현 방향 2가지:
  - (가) 가벼움: 저장 형식은 그대로 두고, **화면에 보일 때 문자열 규칙으로 번역**. 예: `"(성공)"`이 들어 있으면 ✓, `"(실패"`면 ✕, `"현도에게 알림:"`·진단 문구는 부모님 요약에서 제외. 빠르지만 문구가 바뀌면 깨진다.
  - (나) 정석: `LogEntry`에 `kind`(FIXED/FAILED/INFO/DEV)와 `parentText`(부모님 문장)를 추가. 1단계 출품용으로는 (나)를 권하지만, 저장 형식 변경이라 기존 기록 호환(필드 없으면 DEV 취급) 처리가 필요하다.
- 화면: 부모님 영역에는 최근 3~5건만, 관리 영역에는 전체 20건(접힘, 3.6의 P15).
- 왜: 지금 실기 기록처럼 "이미 2회라 더 되돌리지 않았습니다"가 4번 나오면 부모님은 폰이 크게 고장난 줄 안다. 현도는 전부 봐야 한다. 두 요구가 정반대라 나누는 게 맞다.

**P8. 같은 문장 연속 반복은 한 줄로 묶기 ("… (4번)")** — 난이도 소
- 표시할 때만 묶는다. 저장은 그대로.
- 왜: 실기에서 실제로 발생한 문제(같은 줄 4회). 현도용 로그에도 유용하다.

**P9. 날짜를 "오늘/어제" + "오후 3:10" 형식으로, 날짜가 바뀌면 소제목** — 난이도 소
- `"M월 d일 HH:mm"` 대신 오늘·어제는 말로, 시간은 오전/오후 12시간제(어르신에게 24시간제 `22:03`은 덜 익숙). 현도용 로그는 24시간제를 유지해도 된다.

**P10. 최신순 유지 + 각 줄 앞 아이콘(✓ ✕ ℹ)** — 난이도 소
- 지금도 최신이 위인지 확인 필요(`store.log().take(20)`이 저장 순서에 따름). 최신이 맨 위가 아니면 뒤집는다.

### 3.4 버튼 정리

**P11. 부모님 영역의 버튼은 딱 2개(+비상시 중단)로** — 난이도 소
- 부모님이 누를 버튼: [지금 점검하기], [폰이 이상해요], (고치는 중에만) [중단]. 그 외 버튼(설정 열기, 기준 찍기, 다시 자동 복원, 다시 보내기, 데모, 장애 주입)은 전부 관리 영역 또는 "가족이 할 일" 카드 안으로.
- 지금 화면에는 상황에 따라 버튼이 최대 9~10개 있다. 부모님 영역 기준으로 2개로 줄어든다.

**P12. 핵심 버튼 2개를 "큰 타일 버튼"으로** — 난이도 소~중
- 높이 96~120dp, 글씨 26~28sp, 둥근 모서리, 버튼 안에 아이콘+두 줄 문구:
  - [🔍 지금 점검하기 / 폰 설정을 확인해요]
  - [🙋 폰이 이상해요 / 말로 알려 주세요]
- 가로로 두 개 나란히(각 50%)보다 **세로로 하나씩 전체 폭**을 권한다. Flip5 펼친 화면 폭에서 반반이면 한 버튼이 너무 좁아지고 글이 두 줄로 깨진다.
- `Ui.button`에 크기 인자(예: `big = true`)를 추가하는 정도라 쉽다. 둥근 모서리는 `GradientDrawable`로 코드에서 만들 수 있다.

**P13. [중단] 버튼의 일관성** — 난이도 소
- 앱 안 배너는 22sp·96dp, 접근성 오버레이는 30sp·180px(dp가 아닌 px라 기기마다 크기가 다름). 둘을 같은 크기(dp 기준)·같은 문구("멈춰 주세요" 또는 "중단")로 맞춘다. 오버레이 쪽 `minimumHeight = 180`, `setPadding(32, 24, …)`가 px라는 점은 버그에 가깝다.
- 중단 후에는 배너에 "멈췄어요. 그대로 둘게요" 한 줄을 몇 초 보여 주면 눌렀다는 확인이 된다(지금은 기록에만 남음).

**P14. "폰이 이상해요" 입력을 고르기 버튼으로 보완** — 난이도 중
- 지금은 자유 입력 EditText. 어르신은 타이핑이 어렵다. 다이얼로그 안에 큰 선택 버튼 4~5개("전화가 안 와요", "문자가 안 와요", "소리가 안 나요", "인터넷이 안 돼요", "잘 모르겠어요")를 두고, 맨 아래에 "직접 말하기/쓰기"를 남긴다. 선택 버튼은 Liner 분류 없이 바로 `Symptom`으로 매핑되니 망·키가 없어도 정확하다.
- 음성 입력(`RecognizerIntent`)은 키보드 마이크로 이미 가능하므로 별도 구현은 과하다. 힌트 문구에 "키보드의 마이크를 눌러 말해도 돼요"만 추가.
- 왜: 부모님 경로에서 가장 어려운 단계(글자 입력)를 없앤다. 데모에서도 Liner 분류 결과("분류: …" 토스트)를 보여 주는 경로는 직접 입력으로 남는다.

### 3.5 어르신 친화

**P15. 글씨 크기 바닥선 올리기** — 난이도 소
- 부모님 영역 본문 최소 22sp, 상태 카드 제목 30sp 이상. 관리 영역은 지금(18sp)도 괜찮다. 시스템 글꼴 크기 설정을 크게 해 둔 폰이면 sp라 더 커지므로, **상태 카드·큰 버튼은 시스템 최대 글꼴에서 글자가 잘리지 않는지 실기 확인** 필요(줄바꿈 허용, 고정 높이 대신 최소 높이).

**P16. 대비** — 난이도 소
- 검은 글씨 + 흰 배경은 좋다. 문제는 버튼: 주황 `#E65100` 위 흰 글씨는 대비 약 3.8:1로 큰 글씨 기준(3:1)은 넘지만 여유가 없다. 노란 배너 `#FFF3CD` 위 검은 글씨는 충분. 회색 `#546E7A` 위 흰 글씨는 괜찮다.
- 배경을 순백 대신 아주 옅은 회색(`#FAFAFA`)으로, 카드는 흰색+얇은 테두리로 하면 구역이 눈에 들어온다.

**P17. 터치 영역** — 난이도 소
- 버튼 최소 64dp는 이미 좋다(권장 48dp의 1.3배). 버튼 사이 간격을 8dp → 16dp로 늘려 옆 버튼 오터치를 줄인다. 데모 `Switch`는 기본 크기라 작다 — 관리 영역으로 가면 문제 아님.

**P18. 말투 정리** — 난이도 소
- 부모님 영역은 "~해요" 체 + 한 문장 20자 안팎 + 전문 용어 없음으로 통일.
  - "접근성 서비스 (설정 화면 대신 누르기)" → (부모님 카드) "준비가 덜 됐어요. 가족에게 보여 주세요"
  - "같은 이탈이 3일 연속 반복돼 멈췄어요" → (부모님) "같은 일이 자꾸 생겨서 잠깐 쉬고 있어요" / (현도) 원문 유지
  - "기준 상태" → (관리 영역 제목) "정상일 때 모습(기준)"
- 지금 로그 문장 중 "되돌리지 않았습니다"(합쇼체)와 "고쳤어요"(해요체)가 섞여 있다. 부모님용 문장은 해요체로 통일.
- 사람 호칭: 로그에 "현도에게 알림"이 그대로 나온다. 부모님에게는 "아들에게 알렸어요"/"가족에게 알렸어요"가 자연스럽다(앱 설정값으로 호칭을 두는 건 과함 — 그냥 "가족"으로).

**P19. 음성 안내(TTS) 활용 넓히기** — 난이도 소~중
- 지금 TTS(`Announcer`)는 고치기 전 안내에만 쓰인다. 추가 후보:
  - (소) 상태 카드를 길게 누르거나 카드 옆 [🔊 읽어 주기] 버튼 → 카드 문장을 읽음. "폰이 괜찮아요. 마지막 확인은 오후 3시 10분이에요."
  - (소) 점검이 끝나면 토스트만 띄우지 말고 결과 한 줄을 읽어 줌. 토스트(`LENGTH_LONG` 3.5초)는 어르신이 다 못 읽는 경우가 많다. **토스트를 상태 카드 갱신 + TTS로 대체**하는 게 좋다.
  - (과함) 화면 전체를 TTS로 읽는 기능은 시스템 TalkBack이 이미 한다. 대신 각 뷰에 `contentDescription`을 잘 달아 TalkBack 사용 시 "확인 표시"를 "정상"으로 읽게 하는 정도만(소).
- 주의: 한국어 음성이 없으면 `Announcer`가 false를 돌려준다. 그럴 때 화면 문구만으로도 충분해야 한다.

**P20. 토스트 의존 줄이기** — 난이도 소
- "기준을 저장했어요", "분류: …", "먼저 기준을 찍어 주세요" 등 결과가 토스트로만 나온다. 상태 카드 보조 줄이나 결과 카드에 몇 초~다음 점검 전까지 남긴다.

### 3.6 데모·개발용 요소 분리

**P21. 관리 영역을 접히는 "가족·관리용" 섹션으로** — 난이도 소~중
- 화면 아래 [▸ 가족·관리용 (눌러서 열기)] 한 줄. 누르면 기준 상세, 전체 기록, 대기열, 데모 스위치, 통화 기준, 장애 주입, 키 상태가 펼쳐진다. 펼침 상태는 Store에 저장하지 않고 매번 닫힌 채로 시작.
- 한 화면·모든 정보 전제는 지킨다(같은 화면 안에서 접기). `visibility` 토글만으로 된다.
- 왜: 부모님이 데모 스위치를 실수로 바꾸는 사고를 막고, 화면 길이가 절반 이하로 준다.

**P22. 여는 방법에 가벼운 잠금** — 난이도 소
- 단순 탭이면 부모님도 연다. 선택지:
  - 길게 누르기(2초)로 열기 — 권장. 구현이 가장 쉽고 부모님이 우연히 하기 어렵다.
  - 제목 5번 탭(안드로이드 개발자 옵션 방식) — 데모 때 심사위원 앞에서 설명이 필요해 덜 권함.
  - 비밀번호 — 과함.
- 데모 상황(심사)에서는 바로 열 수 있어야 하므로, **데모 모드가 켜져 있으면 처음부터 펼친 상태**로 시작하는 것도 방법.

**P23. 데모 모드 켜짐 표시** — 난이도 소
- 데모 임계값이 켜져 있으면 상태 카드 아래에 작은 띠 "데모 모드 (기준 시간이 짧아요)"를 보여 준다. 켜 둔 채 부모님께 드리는 실수를 막는다.

**P24. 키 상태 줄은 빌드 정보 줄로** — 난이도 소
- "Liner 키 있음 · 텔레그램 없음"에 앱 버전·빌드 시각(BuildConfig)도 붙여 맨 아래 한 줄로. 실기에서 "어느 빌드가 깔렸는지"를 바로 확인할 수 있다(실기 기록상 서명·빌드 혼동이 실제로 있었음). 키 값 자체는 절대 표시하지 않는다(지금도 있음/없음만 표시 — 유지).

### 3.7 색·시각 디자인

**P25. 색에 뜻을 하나씩만 주기** — 난이도 소
- 지금: 파랑(기본·점검), 주황(이상해요), 빨강(중단), 초록(다시 자동 복원), 회색(다시 보내기), 보라(장애 주입), 노랑(배너). 7색이고 색의 뜻이 일정하지 않다(초록이 "정상"이 아니라 "다시 켜기" 버튼).
- 정리안:
  - **주 색(브랜드) = 주황**: 앱 아이콘 주황과 맞춘다. 단, 주황 계열은 "주의"와 헷갈리므로 버튼에는 약간 깊은 주황(`#E8590C` 계열)을 쓰고, 경고에는 노랑을 쓴다.
    - 대안: 주 버튼을 짙은 남색/파랑(`#1565C0` 유지)으로 두고 주황은 제목·아이콘 같은 장식에만. **대비·혼동 측면에서는 이쪽이 더 안전**하다. 둘 중 하나를 고르라면 이 대안을 권한다.
  - 상태 3색: 초록 `#2E7D32`(정상) / 노랑·호박 `#F9A825` 배경 + 검은 글씨(주의) / 빨강 `#C62828`(문제·중단). 이 3색은 상태 카드와 [중단]에만 쓴다.
  - 관리 영역 버튼은 전부 회색 테두리 버튼(흰 바탕+진회색 글씨)으로 낮춘다. 보라·초록 버튼 제거.
- 결과: 부모님 영역에 보이는 색은 상태 카드 1색 + 주 버튼 색 1개 정도로 준다.

**P26. 카드형 구역 + 여백** — 난이도 소~중
- 섹션 제목 24sp 나열 대신, 구역마다 흰 카드(둥근 모서리 16dp, 얇은 테두리 또는 옅은 그림자)로 묶는다. 코드로 `GradientDrawable` 배경을 단 LinearLayout이면 된다. `Ui.card(context)` 도우미 하나를 만들면 전체에 재사용.

**P27. 아이콘** — 난이도 소(이모지) / 중(벡터)
- 1단계는 이모지·유니코드 기호(✓ ✕ ! 🔍)로 충분. 삼성 이모지 글꼴에서 모양이 달라질 수 있어 실기 확인 필요. 출품 완성도를 올리려면 상태 카드 아이콘 3개만 벡터 드로어블로(중).

**P28. 다크 모드** — 과함
- 시스템이 다크 모드여도 지금 코드는 검은 글씨를 고정해 흰 배경이 유지된다. 어르신 대상이면 밝은 화면 고정이 오히려 낫다. 1단계에서는 손대지 않는다.

### 3.8 그 밖에 눈에 띈 것

**P29. Flip5 커버 화면(플렉스 윈도우)** — 난이도 중~대, 1단계에는 과함
- 접은 상태에서 앱을 열면 작은 화면에 이 긴 레이아웃이 뜬다. 지금 위계를 바꾸면(P1) 커버 화면에서도 상태 카드와 버튼 2개가 먼저 보여 자연스럽게 개선된다. 커버 화면 전용 배치는 과하다.

**P30. 취침 시간 입력을 시간 선택기로** — 난이도 소
- 실기 결함 1(형식이 안 맞으면 조용히 기본값 저장)과 연결. `TimePickerDialog`를 쓰면 형식 오류 자체가 사라진다. UI 개선 겸 버그 수정이라 우선순위가 높다. (현도·가족만 쓰는 화면이지만 데이터 정확성 문제.)

**P31. 화면 갱신 시 스크롤 위치 튐** — 난이도 소
- `render()`가 `removeAllViews()` 후 전부 다시 만든다. 점검이 끝나거나 배너가 사라질 때마다 다시 그려서 스크롤이 맨 위로 튈 수 있다. 접히는 관리 영역을 열어 둔 상태가 닫히는 문제도 생긴다(P21 구현 시 펼침 상태를 필드로 기억해야 함). 큰 문제는 아니지만 P21과 같이 처리.

## 5. 구현 방식 의견 (프로그래매틱 View vs XML vs Compose)

**결론: 1단계에서는 지금의 코드 기반 View(프로그래매틱)를 유지하고, `Ui.kt`에 도우미 몇 개를 더하는 방식을 권한다.**

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 프로그래매틱 View 유지 | 의존성 0, APK 작음(현재 약 0.9MB), 빌드가 이 VM에서 이미 안정적으로 돔, 위 제안 대부분(카드·둥근 모서리·접기·큰 버튼)을 `GradientDrawable`·`visibility`로 처리 가능 | 레이아웃이 길어지면 `render()`가 비대해짐, 미리보기 없음 | **권장.** `Ui.card()`, `Ui.bigButton()`, `Ui.statusCard(level, title, sub)`, `Ui.collapsible(title, body)` 4개 정도면 충분 |
| XML 레이아웃 | 미리보기, 스타일·테마 분리 | 지금 동적으로 줄을 만드는 구조(기록 N줄, 멈춘 항목 N개)와 잘 안 맞아 결국 코드와 섞임. 얻는 게 적음 | 비권장 |
| Jetpack Compose | 상태 기반 다시 그리기가 자연스럽고(지금의 `render()` 전체 재생성 패턴과 사실 같은 사고방식), 카드·애니메이션이 쉬움 | Compose 컴파일러·BOM 의존성 추가 → APK 수 MB 증가, 이 VM의 Gradle은 dl.google.com PKIX 문제로 의존성 받기가 번거로움(AGENTS.md 기록), 빌드 시간 증가, 출품 직전 전면 교체는 회귀 위험 | 2단계 이후 화면이 여러 개로 늘거나 상태가 복잡해지면 재검토 |

실무 메모:
- `render()`를 섹션별 함수(`renderStatusCard()`, `renderActions()`, `renderParentLog()`, `renderAdmin()`)로 나누면 지금 구조 그대로도 읽기 쉬워진다. 화면은 하나 그대로다.
- 상태 카드 등급 계산(P4)과 로그 분류(P7)는 Android 없는 순수 함수로 `core/`에 두면 기존 단위 테스트 체계(98개)에 그대로 테스트를 붙일 수 있다. UI 코드에는 결과만 그리게 한다.
- 접근성 오버레이(`AgentAccessibilityService`)도 같은 `Ui` 도우미를 쓰게 하면 배너·오버레이 모양이 자연히 통일된다(P13).
