# UI 개선 2차 1부 구현계획 — 기록 분리(P7·P8) + 타일 버튼·색·카드(P12·P25·P26)

## 1. 설계 결정

### P7: (나) `LogEntry`에 `kind`와 `parentText`를 추가한다
**선택 이유**
- (가)는 개발자 문구에 의존한다. 문구를 하나만 고쳐도 부모님 화면이 조용히 깨지고, 테스트로 잡기도 어렵다.
- 기록을 남기는 시점에는 "무엇을 고쳤는지, 성공했는지, 가족 알림을 실제로 보냈는지"를 정확히 알 수 있다. 부모님 문장은 그때 만드는 것이 맞다. 특히 "가족에게 알렸어요"는 알림을 실제로 보냈을 때만 붙여야 하는데, (가)로는 이것을 보장할 수 없다.
- 저장 형식 변경은 필드를 추가하는 것뿐이다. 읽을 때 기본값만 정하면 앞뒤 버전 모두 호환된다(4장 참고).

**모델**
```kotlin
enum class LogKind { FIXED, FAILED, INFO, DEV }
data class LogEntry(
    val timeMillis: Long,
    val text: String,               // 현도용 원문. 지금과 동일
    val kind: LogKind = LogKind.DEV,
    val parentText: String? = null  // 부모님 문장. 시각은 넣지 않음
)
```
- JSON 키: 기존 `t`/`x`는 그대로 두고 `k`(kind 이름 문자열)와 `p`(parentText)를 추가한다.

**호환 규칙**
- `k`가 없거나 알 수 없는 값이면 `DEV`로 본다.
- `p`가 없거나 빈 문자열이면 `null`로 본다.
- 결과적으로 기존 기록은 부모님 영역에 나오지 않고 관리 영역에만 남는다. 업데이트 직후 부모님 영역은 빈 상태 문구로 시작한다.
- 다운그레이드: 구버전이 `optString`/`getString("t"/"x")`만 읽는다면 새 필드는 무시된다. 실제 파싱 코드가 이 조건을 만족하는지 구현 전에 확인한다.

**부모님 영역 규칙**
- 표시 대상
  - `FIXED`, `FAILED`는 항상 표시한다.
  - `INFO`는 `parentText`가 있을 때만 표시한다.
  - `DEV`는 표시하지 않는다.
- 줄 형식: `{기호} {시각 문구} — {parentText}`
  - 기호: FIXED `✓`, FAILED `✕`, INFO `•`
- 시각 문구
  - 오늘이면 "오늘 오후 3:10"
  - 어제면 "어제 오전 9:05"
  - 그 이전이면 "5월 3일 오후 3:10"
- 문장 규칙: 존댓말 "~했어요" 체로 쓰고, 기술 용어·숫자 상태값·괄호를 넣지 않는다.
  - FIXED: "{설정 이름}를 다시 켰어요/껐어요/되돌렸어요"
  - FAILED: "{설정 이름}를 못 고쳤어요"
    - 가족 알림을 실제로 보낸 경우에만 ". 가족에게 알렸어요"를 붙인다.
    - 보내지 못했다면 ". 가족에게 전화해 주세요"를 붙인다.
- 횟수 제한 차단("이미 2회라…")은 `FAILED`로 분류하고, 문장은 같은 실패 문장을 쓴다. 반복분은 P8에서 묶는다.
- 기준 찍기, 멈춤 해제, QUEUED, 진단은 `DEV`로 분류한다.
- 표시 건수: 묶은 뒤 기준 최근 **5건**, 최신순으로 보여 준다.
- 빈 상태 문구: "아직 고친 일이 없어요".

**관리 영역**
- 전체 20건을 원문(`text`) 그대로, 최신순으로 보여 준다. 기본은 접힌 상태이고 기존 `collapsible`을 사용한다.

### P8: 표시할 때만 연속 반복을 묶는다
- 같은 기록이 **바로 이어서** 반복될 때만 한 줄로 묶는다. 저장은 바꾸지 않는다.
- "같은 기록"의 기준
  - 부모님 영역: `kind`와 `parentText`가 같으면 같은 것으로 본다.
  - 관리 영역: `text`가 같으면 같은 것으로 본다.
- 묶은 줄은 가장 최근 시각을 쓰고, 끝에 " (4번)"을 붙인다. 1번이면 붙이지 않는다.
- 묶기를 먼저 하고, 그다음 5건으로 자른다.

### P25: 주색은 짙은 파랑 `#1565C0`
**선택 이유**
- 깊은 주황 `#E8590C`는 상태색인 노랑·빨강과 색상 거리가 가깝다. 노안이나 백내장으로 색 구분이 약한 분은 "버튼"과 "경고"를 혼동할 위험이 있다.
- 파랑은 상태 3색(초록·노랑·빨강) 중 어느 것과도 겹치지 않는다.
- 흰 글씨와의 대비가 약 5.9:1로 WCAG AA를 충족한다.
- 이미 쓰고 있는 색이라 사용자에게 익숙하다.

**팔레트(색 4종 + 회색 계열, 색 하나에 뜻 하나)**

| 역할 | 색 | 쓰는 곳 |
|---|---|---|
| 주 동작 | `#1565C0` 바탕 + 흰 글씨 | 타일 2개, 확인 버튼 |
| 정상 | `#2E7D32` | 상태 카드만 |
| 주의 | `#F9A825` + 검은 글씨 `#000000` | 상태 카드만 |
| 위험 | `#C62828` | 상태 카드와 [중단]만 |
| 보조 | 흰 바탕 + `#424242` 글씨 + `#9E9E9E` 1dp 테두리 | 관리·가족 영역의 모든 버튼 |
| 카드 | 흰 바탕 `#FFFFFF`, 테두리 `#E0E0E0`, 화면 바탕 `#F5F5F5` | 구역 카드 |

- 보라와 초록 버튼은 없애고 보조 버튼으로 바꾼다.

### P12: 큰 타일 버튼
- 기존 `Ui.button`에 크기 인자를 추가한다.
  ```kotlin
  enum class ButtonSize { NORMAL, TILE }
  fun button(ctx, label, onClick, style = ButtonStyle.PRIMARY, size = ButtonSize.NORMAL, icon: String? = null, sub: String? = null)
  ```
- TILE의 형태
  - 크기: `minHeight` 112dp(고정 높이가 아님 — 시스템 글꼴이 커지면 늘어남), 가로는 `MATCH_PARENT`
  - 모양: 모서리 반경 20dp, 위아래 간격 16dp
  - 아이콘: 왼쪽에 이모지 아이콘 32sp
  - 문구 두 줄: 제목 27sp 굵게, 보조 문구 20sp
- 실제 버튼
  - [🔍 지금 점검하기 / 설정이 괜찮은지 봐요]
  - [🆘 폰이 이상해요 / 가족에게 바로 알려요]
- 두 버튼은 세로로 하나씩, 전체 폭으로 배치한다.
- `bigButton`(104dp)은 TILE로 대체하고 삭제한다. 호출하는 곳도 함께 정리한다.

### P26: 구역 카드
- 상태 카드 아래 구역을 각각 `Ui.card()`로 감싼다: 타일 묶음, 최근 고친 일, 취침 시간, 가족, 관리.
- `card()`의 기본값을 다음으로 맞춘다: 모서리 16dp, 테두리 1dp `#E0E0E0`, 안쪽 여백 16dp, 카드 사이 간격 12dp.
- 접힘 영역(가족·관리)은 카드 안에 `collapsible`을 넣는다.

## 2. 파일별 변경

### 새 파일
- **`core/LogKind.kt`**
  - `enum LogKind`
  - `fun parseLogKind(s: String?): LogKind` — null이나 알 수 없는 값이면 DEV
- **`core/LogPresentation.kt`** (순수 함수, Android 의존 없음)
  - `data class LogRow(val timeMillis: Long, val text: String, val count: Int)`
  - `fun collapseRepeats(items: List<T>, key: (T)->Any, time: (T)->Long, text: (T)->String): List<LogRow>`
    - 바로 이어지는 항목만 `key`가 같으면 묶는다(떨어져 있는 같은 항목은 묶지 않음). `timeMillis`는 묶음 중 **가장 최근** 시각, `count`는 묶인 개수.
    - 입력 순서(최신→과거)를 그대로 유지한다.
  - `fun formatCount(text: String, count: Int): String`
    - `count <= 1`이면 `text`, 아니면 `"$text (${count}번)"`.
  - `fun parentVisible(kind: LogKind, parentText: String?): Boolean`
    - FIXED/FAILED → `true`, INFO → `parentText != null`, DEV → `false`.
  - `fun parentRows(entries: List<LogEntry>, limit: Int = 5): List<LogRow>`
    - `parentVisible`로 거른 뒤 표시 문구(`parentText ?: text`)를 키로 `collapseRepeats`를 적용하고 앞에서 `limit`건을 자른다. **묶은 뒤에 자른다**(묶인 1행이 1건으로 계산됨).
  - `fun kindSymbol(kind: LogKind): String` — FIXED `"✓"`, FAILED `"✕"`, INFO `"•"`, DEV `""`.

- **`core/LogKind.kt`** (새 파일)
  - `enum class LogKind(val code: String) { FIXED("f"), FAILED("x"), INFO("i"), DEV("d") }`
  - `companion fun fromCode(c: String?): LogKind` — 모르는 값이나 `null`이면 DEV.

### 고치는 파일

- **`Store.kt`**
  - `data class LogEntry`에 `val kind: LogKind = LogKind.DEV`, `val parentText: String? = null` 필드를 추가한다(기본값이 있으므로 기존 생성 코드는 그대로 컴파일됨).
  - `toJson()`: `"k"`(= `kind.code`)를 항상 쓰고, `"p"`는 `parentText != null`일 때만 쓴다.
  - `fromJson()`: `optString("k", null)` → `LogKind.fromCode`, `"p"`는 `has("p")`일 때만 읽고 아니면 `null`. 예전 항목은 DEV/`null`로 읽힌다.
  - `fun addLog(text: String, kind: LogKind = LogKind.DEV, parentText: String? = null)`로 시그니처를 확장한다.
  - 저장 개수 상한은 바꾸지 않는다. 부모님 영역은 DEV를 걸러내므로 표시에 필요한 건수가 부족할 수 있지만, 이번 범위에서는 허용한다(4절 참고).

- **`CheckRunner.kt`**
  - 고친 경우(`repair*` 성공 분기)는 `addLog(..., LogKind.FIXED, "○○를 고쳤어요")`로 기록한다.
  - 고치지 못한 경우는 `LogKind.FAILED`와 부모님용 문구로 기록한다.
  - 점검 결과 이상이 없는 경우는 `LogKind.INFO`로 기록하고 `parentText`를 붙인다(예: "점검했어요, 문제 없어요").
  - 내부 진단 문자열(권한 상태, 예외 메시지 등)은 기본값인 DEV를 유지한다.
  - 부모님용 문구는 `CheckRunner` 안의 `private fun parentMessage(result): String?` 한 곳에 모은다.

- **`Ui.kt`**
  - 색 상수: `PRIMARY = 0xFF1565C0`, `OK = 0xFF2E7D32`, `WARN = 0xFFF9A825`, `WARN_TEXT = 0xFF000000`, `BAD = 0xFFC62828`, `BORDER = 0xFFE0E0E0`, 관리 버튼 테두리용 `GREY_STROKE`.
  - `fun tile(ctx, icon: String, title: String, sub: String?, onClick): View` — minHeight 112dp, 아이콘 32sp, 제목 27sp 굵게, 보조 20sp, `MATCH_PARENT` 폭.
  - `fun card(ctx, vararg children: View): LinearLayout` — `GradientDrawable`로 모서리 16dp, 테두리 1dp `BORDER`, 안쪽 여백 16dp, 아래 여백 12dp.
  - `fun statusBadge(ctx, level: Status): TextView` — 3색을 적용하고, 노랑일 때만 글씨를 검정으로 한다.
  - `fun manageButton(ctx, text, onClick)` — 회색 테두리 버튼.
  - `fun logRowView(ctx, row: LogRow, kind: LogKind): View` — 기호, 시각, `formatCount` 결과를 한 줄로 보여 준다.
  - `bigButton`은 **삭제**한다. 남은 호출부는 컴파일 오류로 모두 드러나므로 전부 `tile`로 바꾼다.

- **`MainActivity.kt`**
  - `buildLayout()`을 구역별 `Ui.card(...)`로 감싸는 구조로 재구성한다: 상태 카드, 주요 동작(TILE) 카드, 최근 기록 카드, 관리 카드.
  - `bigButton(...)` 호출을 모두 `Ui.tile(...)`로 교체한다.
  - `renderParentLog()`는 `LogPresentation.parentRows(store.logs(), 5)` → `Ui.logRowView`를 사용한다. 항목이 없으면 "아직 기록이 없어요"를 보여 준다.
  - 개발자용 로그 화면(있는 경우)은 전체 항목에 `collapseRepeats`만 적용하고 DEV도 포함해 보여 준다.
  - 상태 표시는 `Ui.statusBadge`를 사용한다.

- **`res/values/colors.xml`, `themes.xml`**(사용하는 경우): `colorPrimary`를 `#1565C0`으로 바꾼다.

## 3. 테스트 계획

새 테스트는 모두 JVM 단위 테스트로 작성한다(`src/test/.../core/`).

- **`LogPresentationTest`**
  - `collapseRepeats`
    - 빈 목록을 넣으면 빈 결과가 나온다.
    - 연속된 3개가 1행(count 3)으로 묶인다.
    - A,B,A는 묶이지 않고 3행이 된다.
    - 묶음의 시각이 가장 최근 값이다.
    - 순서가 유지된다.
  - `formatCount`: count가 1이면 원문, 2 이상이면 " (N번)"이 붙는다.
  - `parentVisible`: 4종 × parentText 있음/없음 = 8가지 경우를 확인한다.
  - `parentRows`
    - DEV는 제외된다.
    - INFO는 parentText가 없으면 제외된다.
    - 묶은 뒤 5건으로 자른다(반복 10개 + 다른 것 4개 → 5행).
    - 표시 문구는 `parentText`를 우선한다.
- **`LogKindTest`**: `fromCode`가 정상 코드 4개, `null`, 모르는 값 각각을 올바르게 처리한다.
- **`LogEntryJsonTest`**
  - 저장했다가 읽으면 4종 kind와 parentText가 그대로 복원된다.
  - **`k`/`p`가 없는 예전 JSON을 읽으면 DEV/`null`이 된다**.
  - parentText가 `null`이면 `p` 키를 쓰지 않는다.
  - 모르는 `k` 값은 DEV로 읽힌다.
- `CheckRunner`에서 문구를 만드는 부분이 순수 함수로 분리 가능하면 `parentMessage` 매핑 테스트를 추가한다.

**기존 141개 테스트 유지 조건**
- 기존 테스트 코드는 수정하지 않는다. 단, `bigButton`을 직접 참조하는 테스트가 있으면 예외로 `tile`로만 치환한다.
- `LogEntry`와 `addLog`는 기본값으로 확장하므로 기존 호출이 깨지지 않아야 한다.
- 완료 기준: `./gradlew test` 전체 통과(141개 + 신규).

## 4. 위험과 주의 (1부 관련)

**실기 확인 필요**
- **삼성 기본 글꼴(One UI)에서 ✓/✕ 표시**: 기호가 두부(□)로 나오거나 이모지로 바뀔 수 있다. 확인할 내용은 다음과 같다.
  - 기호가 정상 표시되는지 확인한다.
  - 색이 텍스트 색을 따르는지 확인한다.
  - 다른 기호와 폭이 맞는지 확인한다.
  - 문제가 있으면 `kindSymbol`만 바꿔 대체한다(예: "고침"/"실패" 글자 배지).
- **시스템 글꼴 최대 크기(접근성 크기 포함)**: 다음 항목이 잘리지 않는지 확인한다.
  - TILE 제목 27sp가 두 줄로 넘어갈 때 112dp를 넘어 늘어나는지 확인한다. `minHeight`만 쓰고 고정 높이는 금지한다.
  - 로그 행의 " (N번)"이 잘리지 않는지 확인한다.
  - 상태 배지 글씨가 잘리지 않는지 확인한다.
  - 작은 화면(폭 360dp)에서 함께 점검한다.
- 노랑 `#F9A825` 위 검은 글씨, 회색 테두리 대비를 실제 화면 밝기에서 확인한다.

**되돌리기 어려운 변경**
- **저장 형식(`k`/`p` 추가)**: 새 버전은 예전 데이터를 읽을 수 있다. 예전 버전이 새 데이터를 읽을 때 모르는 키를 무시하는지는 기존 `fromJson` 구현에서 확인해야 한다. 무시하지 않는다면 롤백 시 로그를 읽지 못할 수 있으므로, 배포 전에 예전 APK로 새 JSON을 읽는 테스트를 해 본다.
- 업데이트 이전에 쌓인 로그는 모두 DEV로 분류되어 **부모님 영역에 보이지 않는다**. 업데이트 직후 "기록 없음"으로 보이는 것은 의도된 동작이며, 이를 감안해 안내한다.
