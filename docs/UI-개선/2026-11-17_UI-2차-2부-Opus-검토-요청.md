## 2부 요약 (계획 기준)

- P19: 결과 읽어주기 — [🔊 읽어 주기] 버튼만 (길게 누르기 안 씀). 점검 끝 음성은 사용자가 직접 시작한 점검 + 앱이 앞에 있을 때만. TalkBack 켜져 있으면 자동 TTS 끄고 `announceForAccessibility`로 대체. TTS 실패 시 결과 카드에 INFO로 "소리로 읽어 드릴 수 없어요. 화면 글을 봐 주세요."
- P20: 토스트 4종 전부 결과 카드로 이전, Toast 사용 0. 결과 카드는 다음 결과가 생기거나 [확인했어요]를 누를 때까지 유지 (시간 제한 없음). 결과는 SharedPreferences `last_result`(JSON)에 저장.
- 새로 만드는 순수 파일: `core/ResultNote.kt` (`ResultNotes`), `core/SpeechText.kt` (`koreanTime`, `statusCard`, `forSpeech`). 수정: `Ui.kt`, `Announcer.kt`, `MainActivity.kt`, `CheckRunner.kt`, `Store.kt`. 테스트: `ResultNotesTest`, `SpeechTextTest`. 기존 테스트 유지.

## 검토 과제 (코드 수정 금지 — 검토만 한다)

1. **계획-코드 어긋남**: 11/15 계획 작성 이후 바뀐 것들과 계획의 가정이 맞는지 대조한다.
   - 벨소리 복원 수정: `RestorePlan.kt` 신설 (DND를 벨소리 항목 바로 앞으로, API_FIRST 게이트, DEFERRED/ALREADY_OK 결과, 미룬 항목 로그)
   - 점검 후 복귀: `AppReturn.kt` (창 목록 z순서 판정, 뒤로 가기 폴링, DEV 로그 "앱 복귀: ...")
   - 관리용 전체 기록 [복사] 버튼: Toast "복사했어요" 사용 (11/17 추가)
   - MainActivity: 가족용·관리용이 별도 길게 누르기 카드 2개로 분리됨 (1부 구현 시)
   - LogEntry kind/parentText, StatusCard, 타일 버튼 (1부)
   - 테스트 218개
2. **P19**: [읽어 주기] 버튼을 둘 자리 — 현재 MainActivity 구조에서 길게 누르기(관리용 열기)와 충돌 없는지. TTS 조건(직접 시작한 점검 + 앱 foreground) 판정이 현재 코드에서 가능한지. TalkBack 감지 방법. TTS 실패 시 INFO 문구가 들어갈 결과 카드가 P20 카드와 같은 것인지.
3. **P20**: 현재 코드의 Toast 사용처를 전부 찾아라 (grep). 계획은 "토스트 4종 → 결과 카드, Toast 0"인데, 지금 Toast가 몇 개인지, 복사 버튼의 "복사했어요" 토스트는 결과 카드로 바꿀 대상인지 아니면 토스트로 둘 예외인지 판단하라. `last_result` 저장과 StatusCard(마지막 확인) 상태가 겹치지 않는지. [확인했어요] 해제가 다음 점검 결과에 미치는 영향.
4. **새 파일 인터페이스**: `ResultNotes`/`SpeechText`의 계획상 API가 현재 CheckRunner/Store/Announcer/Ui와 맞는지. CheckRunner가 지금 DEFERRED/ALREADY_OK/ReturnReport를 로그로 남기는데, 결과 카드에 담을 "결과"의 범위가 무엇인지 (성공/실패만? 미룸도?).
5. **Manifest `<queries>`**: Announcer가 TTS 엔진 확인에 정말 필요한지, 현재 Announcer 구현을 보고 판단하라.
6. **테스트 계획**: `ResultNotesTest`/`SpeechTextTest`로 충분한지, 깨질 수 있는 기존 테스트가 있는지 (토스트 관련 단언, CheckRunnerTest의 음성 관련 기대값 등).
7. **빠진 것**: 결과 카드가 수동/증상 점검에만 뜨는지 예약 점검 결과도 뜨는지. 계획에 없는 엣지 케이스가 있으면 지적하라.
