# UI 개선 2차 묶음 구현계획 1부 (Claude Router 경유 Opus) — 기록 분리 + 타일 버튼·색·카드

## 당신의 역할
부모님 스마트폰 지킴이 앱 "폰 도우미"의 UI 개선 2차 묶음 중 **1부(기록 분리 + 타일 버튼·색·카드)**에 대한 구현계획을 작성한다. 코드를 직접 고치지 말고, 계획을 마크다운으로 작성해 돌려준다. (2부는 별도 요청으로 나눠서 받는다 — 이 요청에는 1부만 답한다.)

## 앱과 현재 상태
- 앱: "폰 도우미" (`com.hyundo.parentsagent`), 안드로이드 단일 화면 앱. 부모님(70대 이상)이 쓰는 폰의 설정이 잘못 바뀌면 자동으로 되돌려 주는 앱이다.
- 화면은 코드로만 만든 프로그래매틱 View (XML·Compose 없음). `MainActivity.kt`가 `render()`로 화면 전체를 다시 그린다.
- UI 개선 1차 완료: 상단 상태 카드(초록/노랑/빨강), 순서 재배치, 가족·관리용 접기(2초 길게 누르기), 취침 시간 선택기. 단위 테스트 141개 전부 통과.
- 현재 코드 (실측): `android/MainActivity.kt`(화면 전체), `android/Ui.kt`(도우미: `text`, `button`, `card`, `bigButton`(높이 104dp), `statusCard`, `strip`, `collapsible`, `divider`), `android/Store.kt`(`data class LogEntry(val timeMillis: Long, val text: String)`, JSON 저장 키 `t`/`x`), `core/StatusCard.kt`·`core/LongPressGate.kt`(순수 함수 + 테스트).

## 1부 범위
**기록 분리 (P7·P8) — 난이도 중**
- P7: "고친 기록"을 부모님용 요약과 현도용 전체 로그로 나눈다.
  - 부모님용: "무엇을 / 고쳤는지 못 고쳤는지"만. 예: "✓ 오늘 오후 3:10 — 와이파이를 다시 켰어요", "✕ 오늘 오후 3:10 — 비행기 모드를 못 고쳤어요. 가족에게 알렸어요". 부모님 영역에는 최근 3~5건만.
  - 현도용: 지금 로그 그대로(전·후 값, 복원 수단, 진단 문구, QUEUED 같은 상태값, 기준 찍기·멈춤 해제 이벤트). 관리 영역에 전체 20건(접힘).
  - 구현 방향 2가지: (가) 저장 형식 그대로 두고 화면에 보일 때 문자열 규칙으로 번역("(성공)"이면 ✓ 등) — 빠르지만 문구가 바뀌면 깨짐. (나) `LogEntry`에 `kind`(FIXED/FAILED/INFO/DEV)와 `parentText`(부모님 문장) 추가 — 정석이지만 저장 형식 변경이라 기존 기록 호환(필드 없으면 DEV 취급) 필요. **둘 중 하나를 골라 이유와 함께 적고, 호환 처리 방법을 구체적으로 적을 것.**
  - 배경: 지금 기록은 "이미 2회라 더 되돌리지 않았습니다" 같은 개발자 문장이 4번 반복돼 부모님은 폰이 크게 고장난 줄 안다.
- P8: 같은 문장 연속 반복은 표시할 때만 한 줄로 묶는다 ("… (4번)"). 저장은 그대로.

**큰 타일 버튼 + 색 정리 + 카드 (P12·P25·P26) — 난이도 소~중**
- P12: 핵심 버튼 2개([지금 점검하기], [폰이 이상해요])를 큰 타일 버튼으로. 높이 96~120dp, 글씨 26~28sp, 둥근 모서리, 아이콘+두 줄 문구. 가로 반반이 아니라 **세로로 하나씩 전체 폭** (Flip5 펼친 화면에서 반반이면 버튼이 좁아 글이 깨짐). `Ui.button`에 크기 인자를 추가하는 수준.
- P25: 색에 뜻을 하나씩만. 현재 7색(파랑·주황·빨강·초록·회색·보라·노랑)이고 뜻이 일정하지 않음. 정리안: 주 버튼은 짙은 파랑(`#1565C0` 유지, 대비·혼동 측면에서 안전) 또는 깊은 주황(`#E8590C` 계열) 중 하나를 고른다. 상태 3색은 초록 `#2E7D32` / 노랑 `#F9A825` + 검은 글씨 / 빨강 `#C62828`로, 상태 카드와 [중단]에만 쓴다. 관리 영역 버튼은 전부 회색 테두리 버튼(흰 바탕+진회색 글씨)으로 낮추고 보라·초록 버튼 제거. **두 주색 후보 중 하나를 골라 이유를 적을 것.**
- P26: 구역마다 흰 카드(둥근 모서리 16dp, 얇은 테두리)로 묶는다. `Ui.card()` 도우미가 이미 있으니 재사용한다.

## 계획서에 들어갈 것 (1부만)
1. 항목별 설계 결정: P7 (가)/(나) 선택과 P25 주색 선택을 결론 내리고 이유를 적는다. 그 외 모호한 점(부모님용 요약 문장 규칙 등)도 결정을 내려 적는다.
2. 파일별 변경 목록: 새로 만드는 파일, 고치는 파일, 각 파일에서 무엇을 바꾸는지 (함수·필드 이름 수준까지).
3. 테스트 계획: 새로 추가할 단위 테스트 (순수 함수로 뺄 수 있는 로직은 `core/`에 두고 테스트를 붙인다). 기존 141개 테스트 유지 조건.
4. 위험과 주의 (1부 관련): 실기 확인이 필요한 항목 (삼성 글꼴에서 ✓/✕ 기호 표시, 시스템 글꼴 최대 크기에서 잘림 여부), 되돌리기 어려운 변경 (저장 형식 변경).

## 범위 밖
- 2부(P19·P20 카드+TTS, 검증 순서, 작업 순서)는 이번에 쓰지 않는다. 3차(P14, P13, P15~P18), 보류(P5, P24), 하지 않음(다크 모드, 커버 화면, 화면 전체 TTS, 비밀번호 잠금)도 제외. Compose·XML 전환 금지. 코드 기반 View 유지.

## 출력 형식
- 한국어로 작성한 마크다운. 간결하게, 불필요한 반복 없이. 코드 조각이 필요하면 짧게 인용한다.
