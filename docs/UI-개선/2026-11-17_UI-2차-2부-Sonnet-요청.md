- 차단 4건 요약:
  - **B1**: Toast는 계획의 4개가 아니라 **6곳**이다. 점검 결과 토스트(`MainActivity.kt:359`, 분기 4개)가 계획 표에 빠졌고, 그 문구(`outcome.summary`)에는 "현도에게 알렸어요 (SENT)"처럼 이름·내부 값이 그대로 있어 부모님 화면에 쓸 수 없다. 계획:235·241-246 표를 6곳·9문구로 다시 쓰고, 부모님 카드 문장은 따로 만든다고 명시한다.
  - **B2**: `ResultNotes` API가 계획 안에서 세 가지로 갈린다 (필드·직렬화·함수명·종류·liveRegion·카드 수·Manifest·복원 시점). 검토의 권장안(계획:269-283 교체안)으로 하나로 통일한다. 종류는 `LogKind`만, 카드는 1장, 본문은 3줄까지 다 보이게, `strings.xml` 항목은 지우고 문구는 `ResultNotes` 상수로.
  - **B3**: `CheckOutcome.Done`에 기본값 있는 `CheckSummary` 필드를 더한다 (fixed/failed/deferredLabels/stopped/escalated/familyNotified/allClear). `summary` 문자열은 바꾸지 않는다 (기존 단언 7곳 유지). `ResultNotes.forCheck` 우선순위는 summary 분기 순서와 같게: 중단 → 에스컬레이션(알림 성공/실패) → 미룸 → 고침 → 모두 정상. "가족에게 알렸어요"는 `familyNotified=true`일 때만. 카드 범위: 고침·못 고침·미룸·중단·알림 실패는 카드에, ALREADY_OK·앱 복귀 로그·진단 문자열은 DEV 로그에만.
  - **B4**: `Announcer`는 프로세스 공유 인스턴스라 `onPause` stop / `onDestroy` shutdown을 하면 점검의 안전 안내 음성까지 꺼진다. `onDestroy`에서 shutdown하지 않고, `onPause`에서는 [읽어 주기]로 시작한 발화만 멈춘다 (`speakOwned` + `stopUtterance`, utteranceId로 구분). 새 메서드는 `Speaker` 인터페이스에 넣지 않는다 (테스트 Fake 2개가 깨진다).
- 중요 9건도 전부 반영한다 (I1 `lifecycle` 사용 불가 — `android.app.Activity`라 컴파일 안 됨, `resumed` 플래그로 대체 / I2 상태 카드보다 오래된 결과 카드는 숨김 + 저장 키 `result_note`, Store 접근자 / I3 AlreadyRunning은 카드 저장 안 함 / I4 다시 보내기는 결과 콜백 받아서 바꿔 쓰기 / I5 가족·관리 동작은 버튼 근처 피드백, "복사했어요"는 결과 카드로 안 옮기고 버튼 글자 바꾸기로 대체 / I6 분류 결과는 DEV 기록만 / I7 끝 음성은 고침·실패 없을 때와 미룸·중단일 때만 / I8 TalkBack 감지는 `isTouchExplorationEnabled`, liveRegion POLITE, announce는 대체 수단 / I9 [읽어 주기] 버튼은 카드 아래 전체 폭, 흰 바탕+검은 글씨+회색 테두리).
- 제안 S1~S7은 검토 문서대로 판단한다. S1(점검 중 표시)은 2부 범위에 넣을지 정해서 구현한다.

## 0단계 (독립, 먼저): Manifest `<queries>` 추가 (S4)

- `AndroidManifest.xml`에 TTS_SERVICE `<queries>` 선언을 추가한다. targetSdk 36이라 선언이 없으면 TTS 엔진을 못 찾을 수 있고, 지금도 고치기 전 안내 음성이 안 나오고 있을 가능성이 있다.
- 이것은 2부와 별개 항목이라 먼저 하고 빌드까지 확인한다. 엔진 가시성이 실제 원인인지는 실기 로그로만 확정되니, 코드에서 고쳤다고 단정하지 않는다.
