# Opus 검토 요청: 08:00 예약 점검 벨소리 모드 복원 실패

## 사건
- 앱: "폰 도우미" (`com.hyundo.parentsagent`), 부모님 폰 설정 스냅샷 + 주기 비교 + A등급 자동 복원 + 텔레그램 에스컬레이션. 테스트 기기 Galaxy Z Flip5 (One UI 9.0, Android 17).
- 2026-11-16 08:00 예약 점검에서 벨소리 모드 복원(무음 SILENT → 소리 NORMAL)이 실패로 기록됨. 당시 휴대폰은 대기모드(화면 꺼짐).
- 같은 날 13:41 수동 점검([지금 점검하기] 버튼)에서는 같은 복원이 성공함.
- 방해금지(DND)가 08:00에 켜져 있었는지는 미확인. 전체 기록 로그 스크린샷도 아직 못 받음.

## 코드 사실 (검토의 전제 — 이 코드가 실제로 이렇게 돼 있음을 전제로 답할 것)

### 1. 복원 순서 = SettingKey enum 선언 순서 (SnapshotDiff.compare가 entries 순서대로 이탈을 모음)
```kotlin
enum class SettingKey(val label: String, val autoRestorable: Boolean) {
    AIRPLANE_MODE("비행기 모드", true),
    WIFI("와이파이", true),
    MOBILE_DATA("모바일 데이터", true),
    RINGER_MODE("벨소리 모드", true),
    VOLUME_RING("벨소리 볼륨", true),
    VOLUME_MEDIA("미디어 볼륨", true),
    DND("방해금지", true),
    NOTIF_PHONE_APP("전화 앱 알림", true),
    NOTIF_SMS_APP("문자 앱 알림", true),
    SIM_READY("SIM 인식", false),
}
```
→ 벨소리 모드가 방해금지보다 먼저 처리된다.

### 2. 화면 게이트 (ScreenGate) — 접근성 수단이 필요한 항목에만 적용
```kotlin
class AndroidScreenGate(context: Context) : ScreenGate {
    override fun accessibilityBlocker(): String? {
        // 화면 꺼짐 → "화면 꺼짐", 잠금 → "잠금 상태", 통화 중 → "통화 중", 아니면 null
    }
}
val NEEDS_ACCESSIBILITY = setOf(AIRPLANE_MODE, WIFI, MOBILE_DATA, DND, NOTIF_PHONE_APP, NOTIF_SMS_APP)
```
CheckRunner 복원 루프:
```kotlin
if (dev.key in NEEDS_ACCESSIBILITY && gate.accessibilityBlocker() != null) {
    deferred += dev.key; decidedKeys += dev.key; continue  // 판정에 안 넣고, 로그도 안 남기고, 시도 횟수·이탈 일수에도 안 셈
}
```
→ 화면 꺼짐이면 방해금지는 그 점검에서 아예 미뤄지고 로그에도 안 남는다. 벨소리 모드는 NEEDS_ACCESSIBILITY에 없어서 화면 꺼짐에도 시도한다.

### 3. 벨소리 모드 복원 (Restorer) — 직접 API, 재읽기로 판정
```kotlin
SettingKey.RINGER_MODE -> {
    // 실기 확인 필요: 방해금지 중에는 알림 정책 접근 없이 링어 모드를 못 바꿀 수 있음
    audio.ringerMode = ringerModeFor((dev.expected as SettingValue.Mode).name)
    "일반 API (벨소리 모드)" to true
}
// 복원 후 재읽기: expected와 일치하면 SUCCESS, 아니면 FAILED (SETTLE_KEYS에는 WIFI만 있음)
```

### 4. 방해금지 복원 (Restorer.restoreDnd) — 일반 API 먼저, 폴백이 접근성
```kotlin
private fun restoreDnd(service: AgentAccessibilityService?): Pair<String, Boolean> {
    if (nm.isNotificationPolicyAccessGranted) {
        nm.setInterruptionFilter(NotificationManager.INTERRUPTION_FILTER_ALL)
        if (reader.read(SettingKey.DND, false) == SettingValue.Flag(false)) return "일반 API (방해금지)" to true
    }
    // ... 접근성 폴백 (타일/설정 화면)
}
```
→ 방해금지 복원의 1차 경로는 화면이 필요 없는 NotificationManager API다. 그런데도 NEEDS_ACCESSIBILITY에 묶여 있어 화면 꺼짐이면 1차 경로조차 시도하지 않는다.

### 5. 예약 점검 스케줄러
```kotlin
val SLOT_HOURS = listOf(8, 19)
am.setAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, millis, pending(context, slot))
```
→ 08:00 점검은 Doze(절전) 중에도 울린다. 미룬 항목이 있으면 lastCheckMillis를 갱신하지 않아 다음 점검에서 따라잡는다.

### 6. 기타
- 복원 전 TTS 안내 + 1.5~3초 대기. 수동 점검 복원은 일일 횟수에 안 센다. 같은 항목 하루 최대 2회·3일 연속 이탈 시 멈춤 규칙 있음.
- 방해금지 중에는 Android가 벨소리 모드를 방해금지 정책에 묶어 두는 것으로 알려져 있다 (setRingerMode(NORMAL)를 불러도 DND가 켜진 동안은 무음 유지).

## 가설 (검증해 달라는 것)
08:00에 방해금지가 켜져 있었다면: 벨소리 모드 복원이 방해금지보다 먼저 시도돼서, DND 정책 때문에 setRingerMode(NORMAL)가 먹히지 않고 재읽기가 SILENT로 남아 FAILED로 찍힌다. 방해금지 자체는 화면 꺼짐이라 미뤄져서 꺼지지도 않고 로그에도 안 남는다. 13:41 수동 점검 때는 방해금지가 꺼져 있어 같은 호출이 성공한다.
