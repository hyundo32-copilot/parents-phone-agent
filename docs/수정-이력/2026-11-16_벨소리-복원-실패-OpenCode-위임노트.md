## Opus 결정 요약 (자세한 근거는 검토 파일 §1~§2 참고)
- 가설 타당: DND가 우선순위(PRIORITY) 모드면 `setRingerMode(NORMAL)`이 SILENT로 유지돼 재읽기가 SILENT → FAILED. One UI 기본 방해금지는 PRIORITY라 가설 쪽 확률이 높다. 단, DND가 알람만/완전 무음 모드면 오히려 zen이 OFF되면서 성공했을 것이므로 "08:00에 DND가 어떤 필터였나"는 빠진 전제다.

- 추가로: Restorer의 RINGER_MODE 분기에 try/catch가 없어서, 알림 정책 접근이 없을 때 `SecurityException`이 FAILED로 기록되는지 크래시/중단되는지 확인이 필요하다.
- **결정: (a)+(b)+(c) 조합. 핵심은 (a), (b)는 (a)가 있어야 의미 있고, (c)는 비용 거의 없이 다음 재발 때 진단을 가능하게 하므로 포함.**

## 구현 범위 (검토 파일 §3 그대로)
1. **새 파일 `core/RestorePlan.kt` (순수 함수, Android 의존 없음)**:
   - `fun orderForRestore(devs: List<Deviation>): List<Deviation>` — DND를 RINGER_MODE·VOLUME_RING 앞으로. 나머지는 enum 순서 유지.
   - `sealed class DndPath { object Api; object ApiThenAccessibility; object DeferAll }` + `fun dndPath(policyGranted: Boolean, blocker: String?): DndPath` — policyGranted && blocker!=null → Api (실패 시 미룸), policyGranted && blocker==null → ApiThenAccessibility, !policyGranted && blocker!=null → DeferAll, !policyGranted && blocker==null → ApiThenAccessibility(접근성만 실행됨).
   - `fun gateMode(key: SettingKey, blocker: String?): GateMode` (NONE / API_FIRST / DEFER) — 키별로 화면 게이트가 "전부 미룸"인지 "API 선시도"인지.
2. **`RestoreOutcome`에 `DEFERRED(reason: String)` 추가.** 카운트 함수(`countsTowardDailyLimit`, `countsAsDeviationDay`)에서 DEFERRED 제외를 명시할 것.
3. **`CheckRunner` 복원 루프**:
   - `for (dev in RestorePlan.orderForRestore(deviations))`로 순회.
   - `RestorePlan.gateMode(dev.key, gate.accessibilityBlocker())`가 DEFER면 `deferred`에 추가 + DEFERRED 로그 남기고 continue. API_FIRST면 Restorer가 API만 시도하고 실패 시 DEFERRED 반환. NONE이면 그대로.
   - RINGER_MODE·VOLUME_RING은 복원 직전에 재읽기해서 이미 정상이면 호출·카운트 없이 넘긴다 (ALREADY_OK로 로그).
   - DEFERRED는 `deferred`에 추가해 `lastCheckMillis` 미갱신 규칙 그대로 탄다.
4. **`Restorer.restoreDnd(service, apiOnly: Boolean)`**:
   - API 경로 실패 또는 권한 없음이고 `apiOnly`면 `DEFERRED("화면 꺼짐")` 반환.
   - RINGER_MODE 분기에 `try/catch(SecurityException)` 추가 → FAILED("알림 정책 접근 없음")으로 기록하고 루프는 계속한다.
5. **로그 문구**: DEFERRED → `"{label}: 화면 꺼짐이라 잠금 해제 때 고칠게요"`.

## 지키지 말 것 (기존 169개 테스트 유지 조건)
- `SettingKey` enum 순서·label·autoRestorable 불변. **`NEEDS_ACCESSIBILITY` 집합은 그대로 두고 `gateMode`가 그 위에서 판단** (DND만 API_FIRST).
- 기존 "미룸은 카운트 안 함" 테스트는 DEFERRED가 같은 경로를 타므로 통과해야 한다.
- 기존 FakeRestorer 시그니처에 `apiOnly` 기본값 `false` 부여.
- 미뤄진 항목은 시도 횟수·이탈 일수에 안 세는 규칙을 깨지 말 것.

## 테스트 (검토 파일 §3의 8개)
1. `orderForRestore`: DND가 RINGER_MODE·VOLUME_RING보다 앞, 나머지 상대 순서 유지, DND 없을 때 원순서.
2. `dndPath` 4가지 조합.
3. `gateMode`: DND+blocker→API_FIRST, WIFI+blocker→DEFER, RINGER_MODE+blocker→NONE, blocker null→NONE.
4. CheckRunner(FakeRestorer): 화면 꺼짐 + DND API 성공 → DND SUCCESS, 벨소리 SUCCESS, deferred 비어 있음.
5. CheckRunner: 화면 꺼짐 + DND API 실패 → DND DEFERRED 로그 1건, 일일 횟수·이탈 일수 0, lastCheckMillis 미갱신.
6. CheckRunner: DND 복원 후 벨소리 재읽기 정상 → ALREADY_OK, 호출 0회, 카운트 0.
7. 카운트 함수: DEFERRED·ALREADY_OK 제외.
8. Restorer: SecurityException → FAILED, 루프 계속.
- 새 테스트는 모두 JVM 단위 테스트 (`src/test/.../core/` 또는 기존 CheckRunner 테스트 위치). 기존 169개 테스트는 수정하지 않는다.
- 완료 기준: 전체 테스트 통과 (169개 + 신규) + 빌드 성공 + APK 생성.
