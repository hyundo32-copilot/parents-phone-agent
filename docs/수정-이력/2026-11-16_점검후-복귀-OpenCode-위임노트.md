# 점검 후 앱으로 복귀 수정 구현 위임 (OpenCode, Liner 경유 Sonnet 5.5)

## 배경
- 앱: "폰 도우미" (`com.hyundo.parentsagent`), 코드로만 만든 프로그래매틱 View (XML·Compose 없음).
- 문제: [지금 점검하기]를 눌러 수동 점검을 하면, 점검 후에 앱 화면으로 돌아올 때도 있고 안 돌아올 때도 있다. 안 돌아오면 빠른 설정 패널이나 설정 화면에 머무른다.
- 원인 (코드 확인됨): 접근성 복원(비행기 모드·와이파이·모바일 데이터 타일, 앱 알림 설정 화면)은 시스템 화면을 열고, 각 도우미(`toggleTile`, `setSwitchInSettings`, `readAppNotifications`, `setAppNotifications`)가 `finally { performGlobalAction(GLOBAL_ACTION_BACK) }`로 뒤로 가기를 **한 번만** 누른다. 패널이 펼쳐진 상태면 한 번으론 안 접히고, 설정 화면이 깊이 들어갔으면 한 단계만 돌아가며, 타이밍이 어긋나면 뒤로 가기가 먹히지 않는다. 벨소리·볼륨처럼 직접 API로만 고치는 항목이면 앱을 아예 안 떠나서 항상 제자리에 있다.
- 대상 프로젝트: `~/workspace/repos/parents-phone-agent/`
- 현재 상태: 벨소리 복원 실패 수정까지 완료, 테스트 185개 통과, HEAD `9b0eb1f` + 미커밋 변경 있음 (벨소리 수정분). **이 작업은 그 위에 이어서 한다. 커밋은 하지 않는다.**

## 구현 범위
점검 끝날 때 앱 화면으로 명시적으로 돌아오는 안전망을 추가한다. 기존 도우미들의 `finally` 뒤로 가기는 그대로 둔다 (지우지 말 것).

1. **새 포트 `AppReturner` (CheckRunner에 주입, ScreenGate/Restorer 방식과 동일)**:
   - `fun returnToApp()` — 앱 화면으로 돌아오는 시도. 실제 구현은 접근성 서비스에 두고, 테스트용 Fake을 만든다.
   - CheckRunner 생성자에 파라미터로 추가하되, 기존 호출부(AgentRuntime, 테스트 Fake)가 깨지지 않게 기본값을 둔다.
2. **실제 구현 (접근성 서비스, `AgentAccessibilityService`)**:
   - 최대 5회 반복: 현재 최상위 창의 패키지(`rootInActiveWindow?.packageName`)를 읽는다.
     - 앱 자기 패키지(`com.hyundo.parentsagent`, `packageName`으로 읽을 것. 하드코딩 금지)면 이미 돌아온 것이므로 즉시 중단.
     - 우리가 연 시스템 화면이면 뒤로 가기 1회 + 약 400ms 대기 후 다시 확인. 대상 패키지: 빠른 설정 `com.android.systemui`, 설정 `com.android.settings`, 삼성 설정 `com.samsung.android.settings`.
     - **그 외 패키지(사용자가 다른 앱으로 간 경우)면 즉시 중단하고 건드리지 않는다.** 다른 앱에서 뒤로 가기를 누르면 안 된다.
     - 최상위 창을 못 읽으면 잠깐 기다렸다가 반복 안에서 다시 시도하고, 횟수를 다 쓰면 포기한다.
   - 이 메서드는 CheckRunner가 도는 백그라운드 스레드에서 불리므로 블로킹 대기(400ms씩)가 괜찮다. `waitFor` 같은 기존 폴링 방식을 재사용한다.
3. **호출 위치 (`CheckRunner.run` 끝)**:
   - `return CheckOutcome.Done(summary)` 직전에, **trigger가 MANUAL 또는 SYMPTOM일 때만** `returner.returnToApp()`을 부른다.
   - SCHEDULED·UNLOCK 점검에서는 절대 부르지 않는다 (화면 꺼진 채로 앱을 앞으로 가져오면 안 된다).
   - NoBaseline·NoConsent·AlreadyRunning 조기 반환에서는 부르지 않는다 (복원이 안 돌아서 앱을 떠난 적이 없다).
   - 중단(StopController)된 점검에서도 Done 경로면 부른다. [중단] 버튼은 앱 화면에서만 누를 수 있어서 이미 앱에 있는 경우가 대부분이고, 돌아오는 시도는 그때도 무해하다 (이미 앱이면 즉시 중단).
4. **순수 함수로 분리 (`core/`에, Android 의존 없음)**:
   - 최상위 패키지를 보고 돌아올지·뒤로 가기를 누를지·그만둘지를 정하는 판정 함수를 순수 함수로 만든다 (시스템 패키지 집합, 앱 패키지 비교, 최대 횟수 상수 포함).
   - 접근성 서비스는 그 판정 함수를 쓰고 뒤로 가기·대기만 담당한다.

## 테스트
- 순수 판정 함수 테스트: 시스템 패키지 3종이면 뒤로 가기, 앱 패키지면 중단, 그 외 패키지(카톡 등)면 중단, 최상위 창 null이면 재시도·포기.
- CheckRunner 테스트 (Fake AppReturner): MANUAL이면 returnToApp 호출됨, SYMPTOM이면 호출됨, SCHEDULED·UNLOCK이면 호출 안 됨. 기존 185개 테스트는 수정하지 않는다 (Fake 시그니처 변경이 필요하면 기본값으로 호환 유지).
- 완료 기준: 전체 테스트 통과 (185개 + 신규) + 빌드 성공 + APK 생성.

## 구현 방식
- **코드 기반 View 유지, Compose·XML 전환 금지.** 기존 기능(스냅샷·복원 한도·에스컬레이션·안부 신호·TTS 안내) 전부 유지.
- 판정 로직은 Android 없는 순수 함수로 `core/`에 두고 단위 테스트를 붙일 것.
- 뒤로 가기 반복 횟수는 최대 5회로 고정하고, 대기 시간은 400ms 정도로 한다. 무한 루프가 생기지 않게 횟수 상한을 코드에 명시할 것.
