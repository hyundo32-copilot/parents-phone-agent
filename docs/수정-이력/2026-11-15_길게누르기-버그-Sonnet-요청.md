# 가족·관리용 길게 누르기 버그 수정 요청 (Baze Sonnet 5.5)

## 배경

- **버그 재현 (사용자 보고, 2026-11-15)**: "가족·관리용"을 2초 길게 눌러도 반응이 없음. 열리지 않는다.
- 대상 프로젝트: `~/workspace/repos/parents-phone-agent/`

## 원인 분석 (밀리가 코드에서 확인함 — 검증할 것)
- `android/Ui.kt`의 `collapsible(longPressToOpen = true)`:
  - 닫힌 상태에서 ACTION_DOWN 때 2초 뒤 `openTask`를 예약하고, `OnTouchListener`는 `false`를 반환한다 (이벤트를 소비하지 않음).
  - 2초가 지나면 `openTask`가 `set(true)`를 실행해 구역이 열린다.
  - **그런데 사용자가 손을 떼는 순간 ACTION_UP에 대한 클릭 이벤트가 발생하고, `header.setOnClickListener { if (isOpen) set(false) }`가 이미 true가 된 `isOpen`을 보고 즉시 다시 닫아 버린다.** 즉, 2초에 열렸다가 손을 떼는 순간 닫혀서 사용자에게는 "아무 반응 없음"으로 보인다.
  - `openTask` 안의 `header.cancelPendingInputEvents()`는 손을 떼기 전에 실행되므로 아직 발생하지 않은 클릭을 막지 못한다.
- **보조 문제 (UX)**: `MainActivity.render()`에서 접기 헤더 바로 위에 `Ui.divider(this, "가족·관리용")`이라는 똑같은 이름의 구분선 라벨이 있다. 이 라벨은 클릭이 안 되는 일반 텍스트라, 사용자가 이쪽을 길게 눌렀다면 아무 일도 안 일어난다. 헤더와 라벨이 같은 이름을 써서 어느 것을 눌러야 하는지 헷갈린다.

## 수정 요구
1. **핵심 수정**: 길게 눌러서 열린 직후의 클릭(손 떼기)을 무시할 것. 길게 누르기로 열린 뒤 손을 떼도 구역이 열린 채로 남아야 한다. 닫기는 그다음 짧은 탭부터 동작한다.
   - 구현 방법 예시: 길게 누르기로 열렸음을 플래그로 기록하고, `OnTouchListener`에서 그 뒤의 ACTION_UP을 소비(`true` 반환)해 클릭이 발생하지 않게 하거나, 클릭 리스너에서 길게 누르기 직후의 클릭을 시간 기준으로 무시한다. 둘 중 견고한 쪽을 고를 것.
   - `OnLongClickListener` 기본값(500ms)으로 바꾸는 것은 안 된다. 요구사항은 2초다.
2. **보조 수정**: "가족·관리용" 구분선 라벨과 접기 헤더의 이름 중복을 없앨 것. 예: 구분선을 없애고 헤더만 남기거나, 구분선 라벨을 다른 문구(예: "아래는 가족이 관리하는 부분이에요")로 바꾼다. 헤더 문구("▸ 가족·관리용 (길게 눌러서 열기)")는 그대로 둔다.
3. **테스트 가능한 구조로**: 길게 누르기 상태 전이(누름→2초 경과→열림→손 떼기 무시→다음 탭에 닫힘)를 Android 없는 순수 로직으로 `core/`에 분리할 수 있으면 분리하고 단위 테스트를 붙일 것. 분리하기 어려우면 그 이유를 보고에 적고, 최소한 기존 테스트가 전부 통과하는지 확인할 것.
4. "전체 기록" 접기(`longPressToOpen = false`, 짧은 탭 토글)는 건드리지 말 것. 다른 동작은 그대로 둘 것.
