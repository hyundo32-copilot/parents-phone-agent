## 수정 1: 사이드 제스처 패드를 다른 앱으로 오판하는 문제
- 실기 증거 (사용자 Flip5, 2026-11-17 08:06 수동 점검, 관리용 전체 기록): `앱 복귀: LEFT_ALONE, 뒤로 가기 0번, 마지막 화면 com.samsung.android.sidegesturepad`
- 원인 (코드 확인됨): `com.samsung.android.sidegesturepad`는 삼성 엣지 제스처(옆에서 밀어 뒤로 가기) 터치 영역으로, 앱 위에 항상 떠 있는 시스템 오버레이 창이다. `core/AppReturn.kt`의 `topPackage`는 null 패키지·키보드/접근성 오버레이·작은 systemui 창만 빼고 맨 위 창을 고르는데, 사이드 제스처 패드는 그 어느 것에도 안 걸려 최상위 패키지가 된다. `decide`는 앱도 아니고 시스템 화면 3종도 아니라서 LEAVE_ALONE("사용자가 다른 앱으로 갔다")으로 판단해 뒤로 가기를 한 번도 안 누른다. 그래서 앱이 안 돌아온다.
- 고칠 것:
  - 항상 떠 있는 시스템 오버레이 패키지를 빼는 집합을 만든다. 우선 `com.samsung.android.sidegesturepad`를 넣는다. `topPackage`에서 이 패키지의 창은 건너뛴다 (ignorable과 같은 취급).
  - 기존 규칙은 유지한다: 작은 systemui 창(상태 표시줄·내비게이션 바) 제외, 진짜 다른 앱이면 LEAVE_ALONE으로 건드리지 않음, 수동·증상 점검에서만 돌아오기.
  - 판정 로직은 `core/`의 순수 함수로 유지하고, Android 의존은 접근성 서비스 쪽에 둔다.
- 테스트 (`AppReturnTest` 확장):
  - 사이드 제스처 패드가 맨 위여도 건너뛰고 그 아래 창(앱이면 ARRIVED, 설정이면 PRESS_BACK)을 본다.
  - 사이드 제스처 패드 + 진짜 다른 앱이면 LEAVE_ALONE (건드리지 않음).
  - 사이드 제스처 패드만 있고 앱이 아래에 있으면 ARRIVED.
- 완료 기준: 전체 테스트 통과 (기존 210개 + 신규) + 빌드 성공 + APK 생성.

## 수정 2: 관리용 전체 기록 복사 버튼
- 사용자 요청: 관리용 로그를 선택해서 복사하거나, 복사 버튼을 만들어 바로 붙여넣을 수 있게 해달라.
- 고칠 것:
  - 관리용(전체 기록) 구역에 **[복사] 버튼**을 추가한다. 화면에 보이는 최근 20건과 같은 내용을 텍스트로 복사한다 (`Store.log()` + `LogPresentation.adminRows`가 보여주는 것과 같은 줄들, "M월 d일 HH:mm <내용>" 형식으로 한 줄에 하나씩).
  - 안드로이드 ClipboardManager로 복사하고, 복사 뒤에 토스트 "복사했어요"를 띄운다.
  - 기존 표시(접힘·펼침, 줄 묶기)는 그대로 둔다. 복사 버튼은 기록을 바꾸지 않는다.
  - 코드 기반 View 유지, XML·Compose 전환 금지.
- 테스트: 복사되는 텍스트가 화면에 보이는 최근 20건과 같은 줄인지 단위 테스트로 확인한다 (클립보드 자체는 JVM 테스트가 어려우면 텍스트 조립 함수만 순수 함수로 빼서 테스트한다).
