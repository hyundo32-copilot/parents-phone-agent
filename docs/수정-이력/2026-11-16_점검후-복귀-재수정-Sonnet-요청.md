# 점검 후 앱 복귀가 간헐적으로 안 되는 문제 수정 (Baze Sonnet 5.5)

## 배경
- 앱: "폰 도우미" (`com.hyundo.parentsagent`), 코드로만 만든 프로그래매틱 View (XML·Compose 없음).
- 대상 프로젝트: `~/workspace/repos/parents-phone-agent/`
- 현재 상태: HEAD `9b0eb1f` + 미커밋 변경 있음 (벨소리 복원 수정분 + 앱 복귀 1차 수정분). **이 작업은 그 위에 이어서 한다. 커밋은 하지 않는다.**
- 1차 수정 (2026-11-16 17:34, OpenCode): 점검 끝날 때 앱으로 돌아오는 안전망을 넣었다. `core/AppReturn.kt` (순수 판정: 최상위 창 패키지가 시스템 화면 3종이면 뒤로 가기, 앱 자기 패키지면 중단, 그 외 패키지면 건드리지 않음, 못 읽으면 재시도; 최대 5회·400ms 대기), `AgentAccessibilityService.returnToApp()` (최상위 창을 `rootInActiveWindow?.packageName`으로 읽어 `AppReturn.run` 호출), `CheckRunner.run`의 `Done` 반환 직전에 trigger가 MANUAL·SYMPTOM일 때만 호출. 테스트 201개 통과, 빌드 성공.
- **문제 (사용자 실기 보고, 2026-11-16 22:13): 돌아오는 기능이 될 때도 있고 안 될 때도 있다.** 안 될 때는 빠른 설정 패널이나 설정 화면에 머문다 (또는 앱이 아닌 화면에 있다).

## 코드로 확인된 의심 원인 (검증하고 고칠 것 — 단정하지 말고 코드와 Android 동작을 대조할 것)
1. **최상위 창 읽기가 `rootInActiveWindow` 하나뿐이다.** 같은 파일의 `findTile`은 `rootInActiveWindow`와 `windows` 둘 다 훑는다 — 빠른 설정 패널이 활성 창이 아닐 수 있다는 걸 코드가 이미 알고 있다는 뜻이다. 패널이 떠 있는데도 활성 창이 앱 자기 액티비티로 읽히면 판정이 ARRIVED가 되어 뒤로 가기를 한 번도 안 누르고 끝난다. 패널이 활성 창이 되는지는 펼침 상태·포커스에 따라 달라질 수 있어 간헐적 실패와 들어맞는다.
2. **뒤로 가기 후 400ms 고정 대기라 낡은 창 트리를 읽을 수 있다.** 설정 화면이 닫히는 애니메이션·트리 갱신보다 빨리 다시 읽으면, 이미 닫힌 설정 화면을 보고 뒤로 가기를 한 번 더 누른다. 그 뒤로 가기가 앱(MainActivity)에 닿으면 액티비티가 끝나 홈 화면으로 갈 수 있다 — 이것도 "앱으로 안 돌아옴"으로 보인다. 고정 대기가 아니라 창이 실제로 바뀌었는지 확인하고 넘어갈 것.
3. **관측 수단이 없다.** `returnToApp()`은 Unit을 돌려주고 CheckRunner는 결과를 버린다 (`runCatching { returner.returnToApp() }`). 실기에서 안 돌아왔을 때 관리용 전체 기록에 남는 흔적이 없어 다음 진단이 안 된다.

## 구현 범위
1. **최상위 창 판정을 고친다.** `windows` 목록까지 봐서 실제로 화면 맨 위에 있는 창을 가리는 방식을 쓴다 (`findTile`이 쓰는 방식과 같은 접근). 판정 로직은 `core/`의 순수 함수로 유지하고, Android 의존(창 목록 읽기)은 접근성 서비스 쪽에 둔다. "이미 앱이면 뒤로 가기 금지"는 판정 직전의 새 읽기로 다시 확인할 것 (낡은 트리로 한 번 더 누르는 오버슈트 방지).
2. **뒤로 가기 후 대기를 고친다.** 고정 400ms만으로 끝내지 말고, 창이 실제로 바뀌었는지 폴링으로 확인하고(기존 `waitFor`의 250ms 폴링 방식을 재사용), 타임아웃이 지나면 포기한다. 전체 시도 횟수 상한(최대 5회)은 유지한다.
3. **결과를 기록한다.** 돌아오기 시도 결과(ARRIVED / LEFT_ALONE / GAVE_UP, 누른 뒤로 가기 횟수, 마지막에 본 패키지)를 관리용 전체 기록(DEV 로그)에 한 줄 남긴다. `AppReturner`가 Unit이 아니라 작은 결과를 돌려주게 바꾸는 방식이면, 기본값(`NoAppReturner`)과 기존 호출부·Fake가 깨지지 않게 호환을 유지한다.
4. **지킬 것 (바꾸지 말 것).**
   - 수동·증상 점검에서만 돌아오기 (예약·잠금 해제 점검에서는 절대 부르지 않는다).
   - 사용자가 다른 앱으로 갔으면 건드리지 않는다.
   - 기존 도우미들의 `finally` 뒤로 가기는 그대로 둔다.
   - `core/` 판정 로직은 Android 없는 순수 함수로 두고 단위 테스트를 붙인다.
   - 코드 기반 View 유지, Compose·XML 전환 금지. 기존 기능(스냅샷·복원 한도·에스컬레이션·안부 신호·TTS 안내) 전부 유지.
