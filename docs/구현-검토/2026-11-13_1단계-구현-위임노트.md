## 0. 이 앱이 무엇인가 (가족용 돌봄 앱이라는 맥락 — 반드시 읽을 것)

- 이 앱은 **가족용 돌봄 앱**이다. 연로한 부모님이 쓰는 갤럭시 스마트폰에, 자녀인 현도가 부모님과 함께 설치하는 앱이다. 부모님은 스마트폰을 잘 못 써서 설정을 잘못 누르는 일이 잦고, 문제가 생길 때마다 자녀에게 전화가 온다. 이 앱은 부모님이 폰을 계속 쓸 수 있게 돕는 것이 목적이다.
- 설치와 기준 스냅샷은 부모님 폰에서 부모님이 보는 앞에서 직접 설정한다. 앱이 몰래 설치되거나 부모님 모르게 동작하는 것이 아니다.
- 부모님의 통제권이 우선이다. 복원 전에는 TTS로 알리고, "지금 고치는 중" 표시와 큰 중단 버튼을 항상 둔다. B등급은 부모님 음성 확인 후에만 실행하고, C등급은 자동 복원하지 않고 현도에게 넘긴다.
- 수집하지 않는 것: 메시지·통화 내용, 사진, 전체 연락처, 비밀번호. 스냅샷은 설정값(비행기 모드, Wi-Fi, 알림, 볼륨 등)만 저장한다.
- 제3자·직원·타인을 감시하거나 원격 조종하는 앱이 아니다. 대상은 부모님 본인 폰 한 대뿐이다.

## 4. A등급 자동 복원 — 수단과 안전 조건 (설계 문서 §5)

- 무음 해제, 벨소리·볼륨 기준 범위로 복원 (일반 API)
- 전화·메시지 앱 알림 켜짐으로 복원 (일반 API)
- 방해금지 해제 (1단계에서는 접근성 탭으로 설정 화면에서 끈다. 야간 시간대에는 복원하지 않는다. 일반 API로는 Android 15부터 targetSdk 35 이상 앱이 자기 앱 규칙만 끌 수 있어 사용자가 직접 켠 방해금지는 끌 수 없을 수 있다. Flip5 실기에서 확인이 필요하면 미확인으로 보고하라.)
- 비행기 모드 꺼짐으로 복원 (1단계에서는 접근성 빠른 설정 탭으로 끈다. 일반 앱은 Android 4.2부터 비행기 모드를 끌 수 없다.)
- 와이파이·데이터 켜짐으로 복원 (1단계에서는 접근성 탭으로 켠다. targetSdk 29 이상이면 `setWifiEnabled`가 동작하지 않고, 모바일 데이터는 공개 API가 아예 없다.)

공통 안전 규칙:
- 같은 항목의 자동 복원이 하루에 2회를 넘으면 그날은 더 이상 되돌리지 않고 현도에게 알린다.
- 같은 이탈이 3일 연속 반복되면 의도된 변경으로 보고 자동 복원을 멈추고 현도에게 묻는다.
- 야간 시간대(부모님 취침 시간, 스냅샷에 기록)에는 방해금지 복원을 하지 않는다.
- 해외 로밍 중에는 모바일 데이터 복원을 하지 않는다.
- 복원 후에는 TTS로 한 줄 안내하고, "지금 고치는 중" 표시 + 큰 중단 버튼을 항상 둔다.

## 5. Liner API 사용 (앱 런타임)

조작 결정은 규칙 엔진만 한다. Liner는 증상 분류와 에스컬레이션 요약만 맡는다.

- 증상 분류: 부모님 말(텍스트) → Liner 모델 API로 아래 목록 중 하나로 분류. 목록 외의 값이면 증상 버튼 흐름으로 넘어간다. 목록: `SMS_NOT_RECEIVED`, `CALL_NOT_RECEIVED`, `CALL_NOT_MADE`, `CALL_NOT_ENDED`, `SLOW_APP`, `OTHER`.
- 에스컬레이션 요약: 설정 차이, 시도 내역, 전후 수치를 현도가 읽기 쉬운 한국어로 요약한다. 보내는 데이터는 설정값·시도 내역·전후 수치뿐이다. 요약문에서 사람을 이름으로 부르지 마라.
- 망이 끊겼을 때는 Liner를 쓸 수 없으므로 규칙 엔진이 만든 원문을 대기열에 넣고, 망 복구 후 다시 보낸다.
- 호출 스펙: Base URL `https://platform.liner.com/api/v1`, 모델 `liner-mark-1.0`, 인증 `Authorization: Bearer <키>`, `max_completion_tokens` 사용, `reasoning_effort`는 `none` 기본. `temperature`는 서버가 무시한다(`x-liner-ignored-parameters`에 찍힘). 검증된 실측: 증상 분류 7.07초, 요약 2.31초.
- 속도 제한 10 QPS. `429`에는 `Retry-After`를 지켜라.

## 12. 추후 결정 — Opus 지적 수정 (2026-11-13 본인 지시)

구현 Opus 검증 (`2026-11-13_구현-Opus검토.md`, 판정 수정 필요) 중 차단 2건 + 중요 5건(항목 1~7)을 고친다. 제안 8~15번은 이번 범위 밖이다.

1. 로밍 판정 순서: 데이터 항목 판정 직전에 로밍을 다시 읽는다. 이번 점검에서 비행기 모드를 복원했다면 데이터 복원은 다음 점검으로 미룬다. 로밍을 읽을 수 없는 상태(서비스 없음, 예외)는 "로밍일 수 있음"으로 보고 데이터를 복원하지 않는다(fail-closed). CheckRunner 순서 검증 테스트를 추가한다.
2. 심박 건강 게이트: `trySend` 전에 접근성 서비스가 켜져 있는지 확인한다. 꺼져 있으면 보내지 않는다. `HeartbeatSender`에 주입 가능한 `isHealthy: () -> Boolean`으로 넣어 단위 테스트를 쓴다.
3. 벨소리 모드: 기준값을 항상 NORMAL로 복원하지 말고, 기준 `(dev.expected as SettingValue.Mode).name`을 RINGER_MODE_NORMAL/VIBRATE로 바꿔 설정한다.
