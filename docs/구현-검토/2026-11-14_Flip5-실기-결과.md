## 결함 1 — 취침 시간 입력이 기본값으로 조용히 대체됨
- 기준 찍기 대화상자에서 취침 시간을 바꿔 입력해도 저장된 스냅샷은 기본값 22:00~07:00.
- 원인(코드 확인): `parseHm`은 `H:MM` 형식(분 두 자리)만 허용. 형식이 안 맞으면 오류 안내 없이 `?: DEFAULT`로 기본값 저장.
  - `MainActivity.kt:196-197` `parseHm(...) ?: Snapshot.DEFAULT_NIGHT_START/END`
  - `parseHm` 정규식 `^\s*(\d{1,2}):(\d{2})\s*$`
- 영향: 저장된 야간 시간대가 의도와 다르면 방해금지 야간 예외 판정이 달라짐. 실기 당시 저장값은 기본값 22:00~07:00.
- 수정 방향: 파싱 실패 시 기본값으로 조용히 저장하지 말고 오류 안내 + 다시 입력. 또는 시간 선택기(TimePicker) 사용.

## 2026-11-15 후속 — 업데이트 설치 실패와 서명 키 고정

- **증상**: 11/14 22:18 빌드 APK(919,941 bytes)를 기존 설치 앱 위에 업데이트 설치 시도 → 설치 안 됨.
- **원인 (확인됨)**: 서명 키 불일치. debug keystore는 빌드 시 `$HOME/.android/debug.keystore`에 생기는데 빌드는 root로 돌아 HOME=/root라 키가 VM 임시 영역에 생김. VM이 2026-11-15 09:19에 교체되면서 /root가 날아가 키 소실. 11/13 설치본과 11/14 22:18 빌드의 서명이 달라 안드로이드가 업데이트를 거부. versionCode는 둘 다 1로 동일했음 (버전 문제 아님).
- **조치**: `app/debug.keystore` 신규 생성 + `app/build.gradle.kts`의 debug signingConfigs를 `getByName("debug")`로 고정 (`.gitignore`의 `*.keystore`로 커밋 제외). 재빌드 성공 (테스트는 코드 변경 없어 11/14 22:18 기준 98/98 유지, 서명만 변경). 새 APK 서명 SHA-256 `a118e8aa…f352`가 프로젝트 키스토어와 일치 확인. 이후 빌드는 이 키로 서명돼 업데이트 설치 가능.
- **설치 방법**: 기존 앱을 지우고 새 APK로 새로 설치해야 함 (이번 한 번만). 삭제 시 기준 스냅샷·설정 소실 → 설치 후 접근성 켜기·배터리 제한 없음·기준 다시 찍기 필요.
